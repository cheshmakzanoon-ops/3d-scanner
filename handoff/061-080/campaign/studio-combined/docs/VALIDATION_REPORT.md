# RealityForge M01 — Validation Report

**Version:** 0.1.0-m01  
**Validation date:** October 9, 2026  
**Deliverable:** Android source project and host-tested native prototype; no APK or AAB.

## Result at this milestone

The implemented native pipeline extracts matched image features in the host harness, estimates
a calibrated two-camera relationship, rejects unsuitable observations and exports triangulated,
colored sparse points. The Android source connects the native core to photo import, CameraX
capture, project storage, image analysis, a diagnostic viewer and local export controls.

**This is not yet the planned high-quality textured 3D scanner.** There is no dense surface,
texture atlas, multi-camera bundle adjustment or validated reconstruction of a physical object.
The supplied `.glb` uses glTF POINTS primitives, not triangle mesh primitives. `.ply` likewise
contains points and colors rather than faces.

no diagnostics, not a completed Android native-library build.

## Actual synthetic-photo benchmark

Input: two photographs generated by the bundled renderer of a procedurally textured 3D relief.
The third supplied photograph is available for later tests. Geometry is reconstructed from
image correspondences; the known scene and camera are used for evaluation, not supplied as
the reconstructed output.

| Measurement | Observed value |
|---|---:|
| Reciprocal SIFT matches | 589 |
| Accepted triangulated points | 579 |
| Median reprojection error at the fixture's focal calibration | 0.108545 pixels |
| Rotation error against known synthetic camera | 0.045882 degrees |
| Median depth residual | 0.009486 arbitrary synthetic units |
| 90th-percentile depth residual | 0.019457 arbitrary synthetic units |

These measurements apply only to the supplied synthetic fixture and recorded host environment.
They do not establish millimetre accuracy, real-object scan quality, mobile speed, battery
consumption or thermal safety. The fixture is intentionally textured and rigid. Outputs are
in arbitrary scale; no metric measurement feature has been validated.

The source renderer, calibration, input photographs and output files are included so this test
can be reproduced. `reports/synthetic-benchmark.json` preserves its machine-readable results.

## Android source and verification boundary

Source implemented: Kotlin/Compose screens; CameraX JPEG capture; system document import;
private original-photo copies; SHA-256 duplicate detection; EXIF orientation; bounded SIFT
analysis; Room metadata; feature caches; revision and settings fingerprints; invalidation of
stale outputs; JNI calls; diagnostic point viewing; user-directed GLB/PLY exports.

The current Android pipeline examines at most 12 photos and a bounded neighboring-pair set,
then retains a single reliable pair. It does not register all images. Lens calibration is
estimated from EXIF or a disclosed fallback; distortion is not calibrated. Original-photo
preservation, cancellation handling and result publication are implemented in source but still
require execution under Android. Persisted caches permit reruns; arbitrary mid-stage resume
has not been implemented or proven.

The source manifest explicitly removes network permissions and disables app backup. There is
no cloud client, analytics SDK or mandatory login. **Merged APK permissions and offline handset
operation remain unverified because no APK was produced.** The included APK-checking script
and instrumentation tests are intended to verify these properties after a successful build.

### Not run

- Android Gradle compilation, Android lint, JVM Android-module tests or NDK cross-compilation.
- Emulator/device instrumentation, camera capture, gallery import or touch rendering.
- Actual APK permission inspection or ZIP/ELF 16 KB alignment validation.
- Physical-object photography, independent full photogrammetry reference comparisons or device profiling.
- GitHub Actions jobs or any remote deployment. No GitHub repository was created or modified.
- PowerShell bootstrap execution.

## Build environment and dependency caveats

Observed environment: Linux x86_64; JDK 21; CMake 3.31.6; GCC 14.2.0; Clang; Python 3.13.5;
OpenCV 4.13.0; NumPy 2.3.5; pytest 9.0.2. Details are recorded in `reports/environment.json`.

Android SDK, NDK, Gradle, ADB and an Android emulator were not available. The actual Android
build command failed because the wrapper-download host could not resolve. This is an
infrastructure failure before compilation, **not evidence that the Android project compiles**.

The Android project pins OpenCV 4.12.0, and CI pins host OpenCV 4.12.0.88. Local tests used
installed host OpenCV 4.13.0. That version difference must be tested in CI and on-device.
Other pinned build versions and commands are documented in `docs/BUILDING.md`.

The official Gradle wrapper JAR, SDK and third-party dependency caches are not bundled.
First-build dependency installation needs internet access. The app's intended fully offline
runtime does not require an offline build-tool installation.
