# Initial-release candidate qualification, version 1

Qualification consumes the assembled candidate, never99 branch promises. A remote
delivery, compiler success, synthetic fixture or emulator is not physical capture,
complete-object quality, sustained resource behavior, release signing or beta proof.
Run the fixed gate set and retain individual scene/device failures. The tool does
not publish, upload, sign or change repository protection.

## Freeze before measurement

Agent100 supplies a clean integrated source SHA and exact candidate APK/AAB hashes,
plus app/test APK paths, engine/settings/toolchain identity and source-owner matrix.
Create candidate JSON with the contract099 fields. Hash the committed policy file
with SHA256; never remove required gates to obtain PASS. Freeze084/085/087 protocol
hashes and authorized independent reference/eligibility manifests before comparing
optimized results. Obtain at least two real matte textured360-degree objects with
same-lens calibration and disjoint held-out photographs. Keep private originals
outside Git and export/backup existing user projects before device testing.

List every supported physical device/class with API/ABI/build fingerprint, memory
and thermal/charging conditions. Start with12-photo compatibility, then declared
30/100/250 profiles. A current12-photo cap remains a failed larger-profile gate;
the qualifier never silently reduces the product scope. Optional GPU acceleration
stays separately disabled until parity/driver qualification; CPU is required.

## Execute installed app regression

Compile the real app and new instrumentation class using the repository's supported
Gradle workflow, then run from the source checkout:

```bash
python -m tools.release.qualification.journey --candidate /private/candidate.json --apk app/build/outputs/apk/debug/app-debug.apk --test-apk app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk --serial DEVICE_SERIAL --output /private/099-installed
```

The runner checks selected ADB identity, installed candidate APK hash inside the
app test, preserves app data with install-r, imports actual original bytes, verifies
duplicates, loads calibration, runs reconstruction, demands an actual photographic
GLES frame, exports and checks exact model bytes, reopens through a new repository,
checks every original hash and rejects stale revision. No test app data is cleared.
Only the newly created qualification project/temp files are cleaned up. Output is
`journey.json` plus complete `instrumentation.txt`; no attached device yields
BLOCKED_EXTERNAL. ADB nonzero, skipped/zero/incomplete test runs or missing app
receipt fail. Default bundled relief pictures are synthetic; their success does
not satisfy physical or held-out gates.

For real originals, add `--physical-bundle /private/physical-bundle`. That directory
contains bounded `manifest.json` with schema1,kind=physical,authorization_verified=true,
photos3–12 `{filename,sha256}` records and calibration_sha256, plus exact same-lens
`calibration.json` and original JPEG/PNG bytes. Input names must be safe basenames.
The runner verifies every hash/size, rejects emulator execution and copies only
these authorized inputs into a unique `/data/local/tmp/rf099-...` staging directory,
then deletes only that directory. The source files remain unchanged. This adapter
is transport for083-authorized content, not independent proof of permission or truth.

## Full physical journey and operator ledger

The automatic regression covers a useful actual path but leaves required actions
for hardware/UI owners. For each frozen scene/device, execute these steps on the
candidate and retain timestamped logs/screenshots/artifact hashes and per-step
PASS/FAIL/NOT_RUN/BLOCKED_EXTERNAL. A test failure must not be replaced by a manual
claim; fix the owner source and rerun on a newly frozen candidate.

1. Install fresh in an isolated test profile; separately upgrade the previous
   signed candidate with existing test projects. Never uninstall real user data.
   Check project/original hashes before and after migration/reopen.
2. Capture actual CameraX photographs with the same physical lens and separately
   import authorized originals. Exercise permission denial/regrant, orientation,
   lens/zoom mismatch and duplicate handling. Build/validate checkerboard calibration.
3. Review inputs; reconstruct each promised profile; inspect source-visible sides,
   holes and unknown surfaces in the photographic viewer. Orbit/zoom and context
   lifecycle changes must retain correct checker/photographic orientation.
4. Exercise actual reversible orientation/crop/scale/measurement and LOD controls
   when integrated. Check parent artifact/original bytes remain unchanged and
   derived results bind exact edit/settings identities. Missing editing stays NOT_RUN.
5. Export eligible GLB/OBJ/PLY/STL, retain companions and independently validate/
   import/round-trip in target tools. A sparse point file is never mesh qualification;
   arbitrary units require explicit acknowledgement, measured units need provenance.
6. Pause/cancel, force-stop/relaunch and exercise process-death/storage/provider
   faults through088's test-only harness. No incomplete output may become current;
   old originals/results survive. Changed input invalidates stale checkpoints.
7. Record radio state, enable airplane mode, disable Wi-Fi/mobile data and repeat
   the user journey. Confirm no app network permission/traffic; chosen provider
   behavior is separate. Restore the operator's prior radio settings afterward.
8. Run independent084 geometry,085 held-out texture,087 physical resources,
   093 accessibility/TalkBack/font scaling,090 interoperability,096 security,
   095 licenses/dependencies and091 signed/R8/AAB/package gates on exact hashes.

Retain original per-step failures and owner requests, not only retest summaries.
For external beta, recruit authorized independent testers without publishing to a
store; share only the reviewed signed candidate/private consented data. Record
anonymous tester IDs, device/build/data hashes, scenario results, crashes/data loss,
known limitations and critical defect resolution. External testers/signing keys
absent means BLOCKED_EXTERNAL, never a fabricated beta pass.

## Aggregate independent evidence

Store immutable raw logs/reports in a private evidence directory, named by SHA256.
Make schema-valid C16 records referencing those blobs and actual measurement times,
not conversion time. Full084/085 reports can be converted with `quality_adapter`;
limited UV/stereo or unexecuted held-out reports cannot become physical PASS.

```bash
python -m tools.release.qualification.branches --output /private/100-remote-index.json
python -m tools.release.qualification.aggregate --candidate /private/candidate.json --candidate-apk /private/candidate.apk --source-root /private/integrated-checkout --records /private/receipts --evidence-root /private/evidence-blobs --output /private/qualification.json
pytest -q tests/test_release_qualification.py
```

Exit0 is every required exact-candidate gate PASS;1 denotes malformed/mismatched/
failed evidence;2 denotes missing or external blocked gates. The result retains
scene/device status/metrics/blockers individually and has no percentage score.
Schema-valid receipts still need human review: hashes identify bytes, not truthful
authorization. The plan's agent status/ownership index and actual runtime wiring
must agree; all100 remote slots are indexed but branch presence never implies DONE.

Current environment has no attached physical handset or accelerated emulator.
No actual installed journey, physical capture/reference/held-out corpus, sustained
resource matrix, production signing or external beta was executed by099. Its
host tests use explicitly synthetic receipt objects to prove fail-closed behavior.
The final combined candidate must be supplied by100 and independently qualified;
absent physical data/hardware keeps the release blocked.
