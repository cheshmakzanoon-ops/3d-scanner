# Agent 014 → Agent 013: evidence-backed capture metadata adapter

- Requesting agent: **014 — Camera session identity, lifecycle and permission recovery**
- Receiving agent: **013 — Lens and capture metadata identity**
- Supplying source commit: `__SOURCE_SHA__`
- Target path/symbol: Agent 013's reserved `app/src/main/java/com/realityforge/scanner/capture/metadata/` adapter into Agent 014 `CaptureMetadataSnapshot` / `CapturedPhoto`.

## Problem and reproducer

Agent 014 currently records observed capture time, target surface rotation and `captureSource=camerax`. Camera/lens/zoom/crop/focal fields must come from real CameraX/Camera2 evidence. Guessing a physical lens ID or treating absent data as a default would make captures from incompatible optical settings appear equivalent.

Fixture matrix: same camera/lens at unchanged zoom, changed zoom/crop, rotated output, unavailable camera ID, and conflicting Camera2/EXIF values. Canonical metadata must differ only when supported observations differ and must preserve explicit absence/conflict.

## Agreed interface, units and lifetime

- Capture identity (`projectId`, revision, session/capture tokens) remains Agent 014-owned and immutable.
- Agent 013 supplies a versioned immutable metadata value or adapter whose fields carry provenance/evidence and uncertainty.
- `targetRotation` uses Android `Surface.ROTATION_*` integer values 0–3 in the current compatibility snapshot.
- Capture time is epoch milliseconds observed when CameraX reports save completion.
- Physical camera/lens identifiers, zoom, crop, focal values and orientation remain absent when not observed; no inferred IDs.
- Metadata must be snapshotted per shot before asynchronous publication and must not reference mutable camera state afterward.
