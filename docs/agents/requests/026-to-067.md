# Agent 026 → Agent 067 integration request

- Requesting agent: 026
- Receiving agent: 067
- Source commit: `PENDING_AGENT_026_IMPLEMENTATION_COMMIT`
- Target path/symbol: C12 export request/outcome orchestration owned by Agent 067

## Problem and reproducer

Format selection and byte transfer are currently coupled in `ScannerViewModel`. This obscures
provider atomicity, partial-output ownership and exact completion evidence. Agent 026 provides a
format-neutral transfer service and typed outcomes.

## Agreed interface

After eligibility/packaging, Agent 067 supplies `VerifiedExportSource` and an immutable
`DestinationSelectionRequest`. After Agent 001 binds the picker result, call
`DestinationTransferService.transfer`. Map every `TransferOutcome` without converting
`CompletedUnverified` into verified success. Progress is bytes copied versus the fixed expected
byte count. Cancellation remains scoped to the request ID.

Do not encode GLB/OBJ/PLY/STL/ZIP in Agent 026 and do not reopen a different source after the
picker callback.

## Minimal adapter pseudocode

```kotlin
when (val outcome = transfer.transfer(source, destination, cancel, ::publishProgress)) {
    is VerifiedSuccess -> publishVerified(outcome.receipt)
    is CompletedUnverified -> publishWarning(outcome.warning, outcome.recoveryAction)
    is Cancelled -> publishCancelled(outcome.cleanup)
    is Failure -> publishFailure(outcome.kind, outcome.cleanup, outcome.recoveryAction)
}
```
