## Problem and reproducer

Agent 002's C2 graph now performs exact stage-identity reuse and stale-descendant recomputation, but the production durable checkpoint store is intentionally not implemented in Agent 002-owned files. The focused Agent 002 suite proves reuse semantics with a deterministic store; without Agent 009's durable implementation, process-restart reuse cannot be claimed for the integrated application.

Reproducer: run `PipelineGraphTest` on source commit `8bc7e9d20c373fb859ead6278c8c538fec15e3ce`. The tests establish the required identity/reuse behavior; the production app still needs a persistent `PipelineCheckpointStore` wired by its owning agents.

## Agreed interface fields, units, and lifetimes

`PipelineCheckpointStore` must implement:

```kotlin
suspend fun latest(projectId: String, stage: PipelineStage): PipelineCheckpoint?
suspend fun commit(checkpoint: PipelineCheckpoint)
```

A persisted checkpoint must retain, without reinterpretation:

- `PipelineStageIdentity`: stage, full SHA-256 digest, parent digest, project ID, source revision, schema.
- `PipelineArtifactReference`: artifact ID, exact stage identity, representation, primary location, companion locations, optional content SHA-256.
- committed state.

Lifetime: a committed checkpoint must survive Android process death and app relaunch. An in-progress, truncated, checksum-mismatched, wrong-project, wrong-revision, wrong-stage, wrong-representation, wrong-schema, or stale-identity record must never be returned as reusable.

No unit conversion is permitted. C2 identities are opaque SHA-256 values; geometry scale remains whatever the producing stage declared and is not inferred by the checkpoint layer.

## Minimal adapter behavior

```text
latest(projectId, stage):
  read only a fully committed record
  validate schema + project + revision + stage + representation + referenced artifact integrity
  return null (or a typed corruption outcome owned by 009/010) for stale/uncommitted data
  never manufacture a current checkpoint from partial files

commit(checkpoint):
  validate artifact.identity == checkpoint.identity
  durably write metadata/artifact references
  make the record visible atomically only after the referenced artifact is durable
```

Agent 002's `PipelineGraph` already rejects mismatched identities and commits only completed stage output. Do not duplicate or weaken those checks in a parallel pipeline.
