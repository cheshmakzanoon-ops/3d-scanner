# Agent 014 → Agent 017: session-scoped capture guidance

- Requesting agent: **014 — Camera session identity, lifecycle and permission recovery**
- Receiving agent: **017 — Capture guidance, coverage and user feedback**
- Supplying source commit: `__SOURCE_SHA__`
- Target path/symbol: Agent 017 guidance UI/controller; consume Agent 014 `CaptureSessionState` through the identity-bound `CameraScreen.sessionContent` slot and any live evidence through an Agent 016 extension.

## Problem and reproducer

Guidance must not claim a saved image before the bound publication transaction accepts it, and stale analysis from a closed session must not alter the next project's coverage/count state.

Reproducer: take a shot whose repository publication rejects, then open another project while a guidance result is delayed. Saved count remains unchanged and the delayed result cannot affect the new session.

## Agreed interface, units and lifetime

- Treat `CaptureSessionState.savedCount` as committed photographs only.
- Key all guidance state by `CaptureSessionIdentity.sessionToken`; clear token-owned transient state on close/unbind.
- `expectedRevision` advances only from `CaptureCommitOutcome.Accepted` and is not a proxy for optical quality.
- Render through `sessionContent(state)` without owning navigation or CameraX provider binding.
- Use typed/evidence-backed analysis from Agent 016; unknown coverage/focus/lighting remains unknown and is never shown as success.
- Preserve system Back and photo-import access in permission/unavailable states.

## Minimal adapter sketch

```kotlin
CameraScreen(
    session = identity,

    CaptureGuidancePanel(sessionToken = state.identity.sessionToken, state = state)

```

## Affected tests

- rejected publication does not increment guidance count
- stale guidance after session replacement is discarded
- rotation/recreation restores committed count without restoring an in-flight success
- accessible non-visual guidance for failure/unavailable states
