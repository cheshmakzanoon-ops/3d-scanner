# Agent 007 → Agent 005: register durable reconstruction jobs in ScanDatabase

- **Requesting agent:** 007 — Persistent reconstruction jobs and recovery ledger
- **Receiving agent:** 005 — Database schemas, upgrades and durable state model
- **Source commit:** `4460d56109d8f6dae637996b645549e4490fa79b`
- **Target owner paths/symbols:** `app/src/main/java/com/realityforge/scanner/data/Database.kt`; `ScanDatabase`; Agent 005 migration and schema-export paths

## Problem and reproducer

Agent 007 supplies the production Room contracts `ReconstructionJobEntity`, `ReconstructionJobEventEntity`, and `ReconstructionJobDao`, but cannot edit Agent 005's production database file. Until they are registered, `RoomJobStore` can be exercised only through `IsolatedJobStoreDatabase`; application startup cannot construct the authoritative store. The isolated fixture in `DurableJobStoreLeaseDeviceTest`, `DurableJobStoreRecoveryDeviceTest`, `DurableJobStoreStateDeviceTest`, and `DurableJobStoreHistoryDeviceTest` is the executable reproducer for the required schema.

## Agreed interface

Register the two entities and expose `abstract fun jobDao(): ReconstructionJobDao` from the single production `ScanDatabase`. Preserve these stable fields and units:

- identifiers/hashes/codes: bounded strings; all SHA-256 fields are lowercase 64-character hex;
- `projectRevision`, `attempt`, `stateVersion`, progress counters: non-negative `Long`;
- timestamps and lease expiry: absolute Unix epoch milliseconds in `Long`;
- `identityKey`: unique canonical hash of every immutable `JobInputSnapshot` field;
- job events: child rows with `ON DELETE CASCADE`, indexed by `(jobId, eventId)`;
- lease acquisition/mutations: the DAO's compare-and-set predicate on `stateVersion` is mandatory;
- no destructive migration and no interpretation of unknown enum/schema values as defaults.
