# Agent 007 → Agent 088: drive separate-process recovery through stable job identities

- **Requesting agent:** 007 — Persistent reconstruction jobs and recovery ledger
- **Receiving agent:** 088 — Process-death, storage-fault and resume instrumentation
- **Source commit:** `4460d56109d8f6dae637996b645549e4490fa79b`
- **Target owner paths/symbols:** `tools/device/failure_recovery/`; `RecoveryStageContractTest`; controller state capture and assertions

## Problem and reproducer

Agent 007's local instrumentation closes/reopens a real Room database, but it does not itself kill the application process or prove service restart, installed upgrade, physical storage faults, or publication reconciliation. Agent 088 owns those external process/device gates and should assert the durable contract rather than ViewModel recreation.

## Agreed interface

The controller should persist/capture before kill:

- `JobId`, immutable `identityKey`, project revision, attempt, lease token fingerprint (never log the full secret), accepted stage/checkpoint identity/SHA-256, state version, and current terminal/nonterminal state;
- original and staged artifact hashes from their owning manifests.

After relaunch:

- open the production `ScanDatabase` and retrieve the same `JobId` through `JobStore`;
- call `recoverExpired` with Agent 009's verifier only after the old lease expires or is explicitly relinquished;
- assert cancellation remains terminal, changed input stales the old job and creates a new identity, valid same-input checkpoints can resume only at/before the accepted cursor, and stale workers cannot complete/publish;
- keep emulator and physical ARM64 receipts separate; retain every NOT_RUN/FAIL outcome;
- use bounded disposable storage fault fixtures and never exhaust user storage indiscriminately.

## Minimal controller sequence

```text
enqueue/acquire -> accept checkpoint -> record IDs/hashes -> force-stop process
-> wait for lease expiry -> relaunch -> recoverExpired(real verifier)
-> assert PAUSED + same identity/cursor -> explicit resume -> acquire next attempt
-> inject stale old-attempt completion and require rejection
```
