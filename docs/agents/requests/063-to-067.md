# Agent 063 → Agent 067: typed export materialization

Source branch/commit: see final `docs/agents/status/063.md`; contract at `docs/agents/contracts/063.md`. Exact target is Agent 067 ExportCoordinator's native materializer adapter. Consume C10 immutable asset views and the public `stl_export.hpp` API. No current project artifact is opened or overwritten.

`describeStl`/`writeStl` return exact binary bytes, triangle count, selected scale, edge-incidence diagnostics and source provenance. An absent scale is rejected. MetricAsset requires C10 meter positions; Agent 066 already bakes its reference scale into edited meter positions, so never multiply its metersPerOriginalUnit again. KnownReference requires a nonempty evidence ID, finite positive conversion and bounded uncertainty. ArbitraryAcknowledged preserves the explicit unmeasured-scale warning. Target units are meters, millimeters or inches. A private bounded edge map reports open/nonmanifold/orientation conflicts; closure does not assert no self-intersections, manufacturing tolerance or printability. Facet normals use encoded float32 positions, with float32-degenerate/overflowing geometry rejected. No repair, texture, color or material is invented.


Materialize only into private staging streams, retain the returned descriptor/report and close files, then validate and transport via 026. Errors/cancellation/short writes/flush failure must abort the entire export. For multi-file OBJ, archive every descriptor filename at ZIP root, forbid renamed/missing siblings and validate references after extraction. Expected regression: changed selected project while a pending export picker returns cannot change the immutable request's artifact/revision, and any failed transport is not success.
