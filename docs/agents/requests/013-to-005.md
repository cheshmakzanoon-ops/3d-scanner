## Problem and reproducer

`ScanPhoto` currently stores dimensions and `focal35mm` only. It cannot preserve field
provenance, conflicts, physical-camera identity, zoom/crop/orientation or the app-local device
namespace. Reconstructing missing fields from nullable columns would turn unknown evidence into
assumptions and can reuse a calibration after optics change.

Reproducer: encode two `CaptureMetadata` records that differ only in zoom, crop, orientation,
physical camera or `captureDeviceId`. Their
`CaptureMetadataCodec.opticalIdentitySha256(...)` values differ. A row model that stores only
width/height/focal35 cannot preserve or invalidate those differences.

## Required additive persistence contract

Add nullable fields to the photo/capture record, with names selected by Agent 005 but semantics
fixed as follows:

1. **Canonical metadata bytes** — BLOB containing exactly
   `CaptureMetadataCodec.encode(metadata)`, maximum 65,536 bytes.
2. **Metadata schema version** — INTEGER matching `CaptureMetadata.schemaVersion`; null when the
   blob is null. Reject unsupported versions through the codec rather than reading defaults.
3. **Optical identity SHA-256** — lowercase 64-hex TEXT equal to
   `CaptureMetadataCodec.opticalIdentitySha256(metadata)`. Store/update it transactionally with
   the canonical blob and photo row.
4. **Durable capture-device namespace** — one random opaque installation-local identifier,
   created once in durable app state and supplied to camera/session owners. It is not a hardware
   serial, advertising ID, account ID or telemetry key. Rotation/restart must not change it.

For existing version-1 rows, migrate all three metadata fields to null. Do not synthesize normal
orientation, 1x zoom, full crop, a lens ID or a device namespace. Existing width/height/focal35
columns may remain as legacy/index/display fields until their owner migrates readers, but the
canonical blob is authoritative for new metadata-aware logic.

## Units and lifetimes

- Dimensions: encoded pixel width/height.
- Orientation: all eight EXIF orientations.
- Focal values and sensor dimensions: millimetres.
- Zoom: unitless ratio.
- Crop: integer sensor-active-array coordinates plus its reference rectangle.
- Device/session/camera IDs: bounded UTF-8 strings, maximum 256 characters.
- The metadata and optical identity are immutable for one committed original photo. A corrected
  metadata record creates a new input revision and invalidates dependent artifacts.

## Minimal adapter shape

```kotlin
data class StoredCaptureMetadata(
    val schemaVersion: Int,
    val canonicalBytes: ByteArray,
    val opticalIdentitySha256: String,
)

fun StoredCaptureMetadata.decode(): CaptureMetadata =
    CaptureMetadataCodec.decode(canonicalBytes).also {
        require(it.schemaVersion == schemaVersion)
        require(CaptureMetadataCodec.opticalIdentitySha256(it) == opticalIdentitySha256)
    }
```

DAO publication must write the photo row, canonical blob, version and identity in one
transaction. Readers must return explicit missing metadata for old rows, not fabricate a
`CaptureMetadata` instance with defaults.
