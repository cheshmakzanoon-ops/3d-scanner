## Problem and reproducer

Agent 002 now distinguishes completed sparse, dense, observed-mesh, and photographic-mesh outcomes. A failed texture stage remains `Unavailable` and does not masquerade as photographic success. The legacy adapter still performs its historical file writes so the M19 path remains compatible; final integration must route validated completed artifact references through Agent 023's atomic publisher without losing the last valid completed result.

Reproducer: on source commit `8bc7e9d20c373fb859ead6278c8c538fec15e3ce`, `PipelineGraphTest` exercises partial/cancelled outcomes and `DensePreview.reconstructTyped` emits distinct surface/texture outcomes.

## Agreed interface fields, units, and lifetimes

The publisher must consume immutable, revision-bound data equivalent to:

- project ID and exact source revision;
- requested terminal stage;
- completed `PipelineArtifactReference` values only;
- each artifact's stage identity and representation;
- primary and companion artifact locations;
- optional content SHA-256;
- structured unavailable/failure information separately from completed artifacts.

Publication success must mean the complete selected artifact set is durably visible for the same project revision. Cancellation, storage failure, stale revision, or an unavailable downstream stage must leave the previous completed result intact.

Representation is semantic and must not be inferred from a filename:
`SPARSE_POINTS`, `DENSE_POINTS`, `OBSERVED_MESH`, and `PHOTOGRAPHIC_MESH` remain distinct. Geometry scale is arbitrary unless another validated contract supplies a scale reference.

## Minimal adapter behavior

```text
publish(request):
  verify project/revision is still current
  verify every completed artifact identity belongs to that project/revision/stage
  stage/copy/fsync required files under temporary names
  validate required hashes/sizes
  atomically commit metadata/current-result pointer only after all required artifacts are durable
  on cancellation/failure/stale revision:
    remove partial publication files
    keep prior completed result/current pointer unchanged
```

If texture is unavailable but surface completed, publish/retain the observed mesh as the highest valid representation; do not create a textured-success record.
