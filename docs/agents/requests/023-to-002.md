## Problem / reproducer

The current pipeline writes JSON, sparse GLB/PLY, dense outputs, mesh, and texture paths sequentially. A kill after any rename can leave a mixed set, while later metadata completion refers only to one key. Agent 023 provides one immutable multi-artifact set and journal, but cannot edit this owner file.

## Agreed interface

Construct `PublicationIdentity(RESULT_SET, projectId, revision, operationId, attempt, inputSha256, settingsSha256, engineVersion)` from durable job and Agent 009 identity data. Use `ArtifactPublicationSessionFactory.beginResult(identity, declarations)`. Declarations carry logical name, safe relative path, representation, required flag, and maximum bytes. Stage actual producer files/bytes; omit unavailable optional outputs rather than creating placeholders; call `publish()` only after every required producer succeeds.

The session and filesystem calls are blocking and belong on the pipeline's I/O context. Operation ID/attempt are immutable for one attempt. Artifact byte/hash identity is calculated while staging.

## Minimal adapter sketch

```kotlin
val session = publication.beginResult(identity, declarations)
session.stageBytes("preview", output.toString().toByteArray())
session.stageFile("sparse-glb", generatedSparseGlb)
// Stage optional dense/mesh/texture only when genuinely produced.
val verified = session.publish()
```

Remove only the sequential final publication path after this adapter is integrated; keep producer generation/cancellation behavior.
