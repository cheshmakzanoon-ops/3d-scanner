# Agent 007 → Agent 023: fence atomic publication with the current lease and revision

- **Requesting agent:** 007 — Persistent reconstruction jobs and recovery ledger
- **Receiving agent:** 023 — Atomic result publication and last-completed preservation
- **Source commit:** `4460d56109d8f6dae637996b645549e4490fa79b`
- **Target owner path/symbols:** `app/src/main/java/com/realityforge/scanner/data/publication/`; `ArtifactPublicationSession` and final metadata commit

## Problem and reproducer

A worker can finish expensive computation after its lease expires, after a new attempt starts, or after project inputs change. Publishing staged files before checking the current attempt and revision can expose stale output. `DurableJobStoreLeaseDeviceTest` proves old attempt/token/state-version capabilities are rejected; `DurableJobStoreRecoveryDeviceTest` proves changed input stales the old job.

## Agreed interface

Immediately before the atomic publication transaction:

1. call `JobStore.validateLease(lease, nowEpochMillis)`;
2. require `snapshot.state == RUNNING` and exact job ID/attempt/token/worker/state-version equality;
3. compare the current project revision and immutable input identity with `snapshot.input.projectRevision` and `snapshot.identityKey` inside the publication transaction/lock boundary;
4. verify every required artifact through Agent 009;
5. publish the complete set atomically while preserving the last completed set;
6. call `JobStore.complete` with the same current lease and the verified result artifact identity/SHA-256.

If the lease or revision changes between staged-file work and commit, do not update current-result pointers and do not call `complete`. Record/reconcile unreferenced staged files through Agent 023's journal; the job ledger does not authorize deletion by itself.

## Minimal adapter pseudocode

```kotlin
val current = jobStore.validateLease(lease, clock.nowMillis())
publicationPort.commitIfCurrent(
    projectId = current.input.projectId,
    expectedRevision = current.input.projectRevision,
    expectedInputIdentity = current.identityKey,
    attempt = current.attempt,
    artifactSet = verifiedSet,
)
jobStore.complete(
    lease,
    verifiedSet.identity,
    verifiedSet.manifestSha256,
    clock.nowMillis(),
)
```

The final publication port must recheck revision and lease fencing at its durable commit boundary; an earlier UI or runner check is insufficient.

## Affected tests

- Agent 023 fault injection at stage-write, rename, metadata-commit, and job-complete boundaries.
- Agent 007 stale/superseded lease instrumentation.
- Agent 088 kill/relaunch and short-write/ENOSPC cases.

## Expected verification

```text
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
./gradlew :app:connectedDebugAndroidTest
```

Inject a lease renewal, expiry, retry/new attempt, project revision change, process kill, and repeated reconciliation at every publication boundary. No stale/partial artifact set may become current, and the prior completed result must remain accessible.
