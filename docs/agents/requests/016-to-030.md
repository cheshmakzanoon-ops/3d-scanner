## Problem and reproducer

Agent 016 currently provides a conservative static budget. Production capture needs a dynamic policy that can reduce analysis cadence and retained luma size under measured memory/thermal pressure without changing ImageProxy ownership or blocking camera capture.

## Required provider semantics

Implement or adapt Agent 030 scheduling state to `CaptureAnalysisBudgetProvider`:

- `currentBudget()` must be nonblocking, side-effect-free and safe on the CameraX analysis executor.
- Return only valid `CaptureAnalysisBudget` values and change them through immutable snapshots.
- Under pressure, reduce cadence/edge/retained bytes conservatively; do not increase work based on unmeasured assumptions.
- Do not retain an `ImageProxy`, full-resolution frame or Agent 016 analyzer instance.
- Do not call back into CameraX binding or UI code.
- Record the reason for a budget tier in Agent 030 diagnostics; Agent 016 exposes only bounded counters and does not claim physical resource qualification.

The stream analyzer already detects a budget shrink, discards a retained frame that no longer fits and resets action smoothing. Add an integration test that exercises that transition with the real provider.

## Affected tests

Agent 030-owned tests should cover normal, memory-pressure, thermal-pressure and recovery tiers; invalid data must fail before reaching production. A combined test must assert retained bytes never exceed the current budget and that normal capture remains available when analysis is throttled.
