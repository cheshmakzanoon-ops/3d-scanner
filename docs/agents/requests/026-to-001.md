# Agent 026 → Agent 001 integration request

- Requesting agent: 026
- Receiving agent: 001
- Source commit: `PENDING_AGENT_026_IMPLEMENTATION_COMMIT`
- Target path/symbol: `ScannerViewModel`/activity-result export composition owned by Agent 001

## Problem and reproducer

The current picker callback calls export using mutable selected project state. A project change
between launching `CreateDocument` and receiving its URI can select a different source. Agent
026 unit regression `pickerCallbackCannotSwitchSourceProjectOrRevision` demonstrates the
required rejection behavior.

## Agreed interface

Persist an immutable `DestinationSelectionRequest` for each launched picker. It carries request
ID, exact `ExportSourceIdentity`, display name, MIME type and create-vs-existing mode. Convert
the activity result into `DestinationSelectionCallback`, then call `request.bind(callback)`.
Only a `DestinationBindingResult.Bound` may enter Agent 067 orchestration.

IDs and revisions remain stable for the request lifetime. Do not reconstruct the identity from
`selectedId`, current preview or latest project state after the picker returns.

## Minimal adapter pseudocode

```kotlin
val pending = exportCoordinator.begin(format)
launcher.launch(pending.displayName)
// callback
val bound = pending.destinationRequest.bind(callbackFor(uri))
exportCoordinator.transfer(bound)
```

Keep pending requests in saved application state or explicitly fail them after recreation; do
not silently attach a callback to another request.
