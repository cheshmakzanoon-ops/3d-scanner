# Agent 014 → Agent 015: optical controls through the session extension seam

- Requesting agent: **014 — Camera session identity, lifecycle and permission recovery**
- Receiving agent: **015 — Camera optical controls and device capabilities**
- Supplying source commit: `__SOURCE_SHA__`
- Target path/symbol: Agent 015's owned optical-control implementation; integrate via `CaptureSessionExtension` from `capture/session/CaptureSessionExtension.kt`.

## Problem and reproducer

Independent CameraX binding/unbinding by optical controls would race Agent 014 disposal and leak or tear down another session's use cases. Async focus/zoom results can also arrive after navigation and must not mutate a replacement session.

Reproducer: issue focus/zoom, press Back before completion, open a new session, then release the old completion. The new session state and controls must remain unchanged.

## Agreed interface, units and lifetime

- Supply zero or more session-scoped `UseCase` objects through `CaptureSessionExtension.useCases` before binding.
- Receive the bound `Camera` and immutable `CaptureSessionIdentity` only through `onCameraBound`.
- Never call `ProcessCameraProvider.bindToLifecycle`, `unbind`, or `unbindAll` independently.
- Release listeners/references in `onCameraUnbound(sessionToken)` and ignore callbacks whose token is no longer active.
- Report capability absence and control failures explicitly; do not synthesize successful focus/exposure/zoom state.
- Any metadata observation passed to Agent 013 is a per-shot snapshot, not a mutable camera reference.

## Minimal adapter sketch

```kotlin
class OpticalControlsExtension : CaptureSessionExtension {
    override fun onCameraBound(identity: CaptureSessionIdentity, camera: Camera) {
        activeToken = identity.sessionToken
        // Observe capabilities and issue controls through camera.cameraControl.
    }
    override fun onCameraUnbound(sessionToken: String) {
        if (activeToken == sessionToken) clearListenersAndReferences()
    }
}
```

## Affected tests

- capability matrix and unsupported controls
- delayed focus/zoom callback after disposal/replacement
- extension never owns provider binding
- controls survive pause/resume only for the same token
