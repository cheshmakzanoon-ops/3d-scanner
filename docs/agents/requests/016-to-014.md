# Agent 016 to Agent 014 — bind live quality analysis to camera-session lifecycle

## Problem and reproducer

The current camera path binds Preview and ImageCapture but no ImageAnalysis use case. Agent 016 cannot edit the camera binding owned by Agent 014. Without binding, the analyzer is implemented and tested but cannot receive live frames or prove session-stale suppression in the real lifecycle.

## Required adapter

For each new camera-session generation:

1. Create a fresh opaque `CaptureAnalysisSessionId` from the Agent 014 session token.
2. Construct one `CameraXCaptureQualityAnalyzer` with the production budget provider, retained-photo threshold provider when available, and callbacks that first compare `observation.sessionId` with the currently active session.
3. Create the use case through `CaptureQualityImageAnalysis.create(executor, targetRotation, analyzer)` and include it in the same `bindToLifecycle` transaction as Preview and ImageCapture.
4. On permission loss, lifecycle stop, camera rebind, or session replacement: invalidate the current session, clear rendered quality state, close the old analyzer, clear/unbind its ImageAnalysis use case, then release its executor according to Agent 014 ownership.
5. Analyzer failure must be diagnostic only. It must not disable shutter/capture or convert an unknown state into READY.

Minimal pseudocode:

```kotlin
val token = CaptureAnalysisSessionId(activeCameraSessionId)
val analyzer = CameraXCaptureQualityAnalyzer(
    sessionId = token,
    budgetProvider = liveBudgetProvider,
    thresholdProvider = thresholdProvider,
    onObservation = { observation ->
        if (observation.sessionId == activeToken) publishQuality(observation)
    },
    onFailure = ::recordNonBlockingAnalysisFailure,
)
val qualityUseCase = CaptureQualityImageAnalysis.create(executor, targetRotation, analyzer)
// Bind Preview + ImageCapture + qualityUseCase atomically for this session.
```

Add Agent 014-owned lifecycle tests for session A→B replacement, permission recovery, rotation/rebind, close-during-read, and capture remaining available after analyzer failure. Reuse `stateSnapshot()` only for diagnostics, not user-facing progress.
