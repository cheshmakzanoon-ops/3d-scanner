# Agent 006 → Agent 021: compose storage reservations with project reservations

- Requesting agent: 006
- Receiving agent: 021
- Contract: `docs/agents/contracts/006.md` (`c6-v2`)
- Target path/symbol: storage preflight, byte reservations and peak-space accounting

A byte/storage reservation is not project ownership. Long operations must first establish the bound
C6 request, then obtain the bounded storage reservation without releasing C6 or changing destination
identity. Define one acquisition/release order used by import, reconstruction, publication, archive
and deletion recovery so storage pressure cannot create a cross-service deadlock.

Required tests: denied/expired space reservation, concurrent jobs on different projects, cancellation
at every acquisition point, storage exhaustion after partial write, and proof no incomplete result is
published when capacity changes.
