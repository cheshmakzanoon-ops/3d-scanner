## Problem and reproducer

Blur/exposure/motion evidence and overlap/diversity evidence are separate measurements. Presenting either as a fabricated combined percentage or letting a stale quality observation authorize capture would violate the product contract.

## Agreed interface and composition rules

Consume `CaptureQualityObservation` by exact `CaptureAnalysisSessionId` and monotonically increasing `sequence`.

- `UNAVAILABLE`, `WAIT_FOR_EVIDENCE`, and `MOTION_UNAVAILABLE` remain unknown; they cannot be treated as adequate overlap or as READY.
- `ACTION_REQUIRED` may provide a blocking corrective action while overlap evidence remains independently visible.
- `ACCEPTABLE/READY_TO_CAPTURE` means only that the bounded luma checks passed. Agent 017 must still evaluate measured overlap/diversity.
- Preserve typed `evidenceCodes`; do not average `confidence` with overlap scores.
- On session change, clear both quality and overlap evidence before accepting new observations.

Suggested composition shape:

```kotlin
data class CaptureGuidanceInput(
    val sessionId: CaptureAnalysisSessionId,
    val quality: CaptureQualityObservation?,
    val overlap: OverlapObservation?,
)
```

The resulting UI action should retain the strongest measured corrective reason and explicitly represent missing evidence.

## Affected tests

Add table-driven composition tests for quality unknown + overlap good, quality bad + overlap good, quality good + overlap bad, both good, stale session IDs, and out-of-order sequences.
