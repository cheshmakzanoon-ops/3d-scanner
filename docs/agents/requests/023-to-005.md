## Problem / reproducer

Current `state(PROCESSING)` clears result pointers before a rerun and `complete` installs one key. A failed or stale rerun can therefore make the last completed result inaccessible, and no transaction can atomically bind a verified artifact set to operation/attempt/revision.

## Required persisted fields and transaction

Provide a Room-backed `PublicationMetadataPort` with:

- project publication CAS epoch (`metadataVersion` in Agent 023 API); increment only when revision, active operation/attempt/state, or current publication pointer changes, not for unrelated UI progress;
- current and previous completed result pointers, including set ID, manifest SHA-256, relative directory, purpose, project revision, operation ID, attempt, publication time, and durability flags;
- a committed-publication table/index keyed by `(projectId, setId)` so `committedPointer` also finds original-import batches;
- active durable job operation ID, attempt, and state supplied by Agent 007.

`commit(request)` must be one transaction. Recheck project existence/deletion, exact revision, RUNNING operation/attempt, expected current set ID, and expected CAS epoch. For `RESULT_SET`, move old current to previous and install new current. For `ORIGINAL_IMPORT`, record the import pointer, apply the corresponding staged input rows, increment revision, clear stale current, and move old current to previous. Return the resulting current/previous pointers.

Never clear current/previous merely because processing starts. Unknown pointer schema versions must be rejected or migrated explicitly.
