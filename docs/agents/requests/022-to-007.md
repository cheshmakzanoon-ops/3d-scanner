# Agent 022 -> Agent 007: deletion lease and job exclusion

Please implement the `DeletionLeaseCoordinator` side of durable job acquisition.

- A committed logical tombstone prevents every new import, capture, reconstruction, export,
  curation, cache cleanup, and result-publication lease for that scope.
- `acquire` either returns one serialized cleanup lease or the exact typed current blockers.
  Current work is not force-relabelled complete; it drains/cancels according to its own contract.
- `release` is idempotent. Releasing cleanup must not admit new work while the tombstone remains
  non-completed. Recover stale process-owned leases without losing the tombstone.
- Exercise races between deletion and job acquisition, stale completion, two projects, repeated
  recovery, and publication attempting to commit after deletion confirmation.

Map blockers to the existing `DeletionBlocker` values rather than free-text errors.
