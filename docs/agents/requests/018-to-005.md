# Agent 018 -> Agent 005: persist curation atomically

- Requesting agent: 018

## Problem and reproducer
The schema stores one project revision and no curation state, position, exclusion reason, pending-removal identity, or curation version. A process restart therefore cannot preserve Agent 018 state, and compare-and-set commits cannot be atomic.

## Interface
Persist every field needed to reconstruct `CurationSnapshot`: stable photo ID/hash, contiguous position, state, typed exclusion reason/note, pending request ID/timestamp/reason, previous state/exclusion, `projectRevision`, and `curationVersion`. Active pending request IDs must be unique per project. Implement a Room transaction matching `PhotoCurationStore.commit(CurationCommitRequest)` that compares both expected revisions, writes all rows/revisions, applies invalidation when `change.projectRevisionChanged`, retains the previous completed result under Agent 023's contract, and returns the exact committed snapshot.

## Minimal adapter pseudocode
`@Transaction commit(req) { current = readForUpdate(req.projectId); if (current.revision != req.expectedRevision) return Conflict; replaceOrderedRows(req.nextSnapshot); updateRevisions(...); if (req.change.projectRevisionChanged) markCurrentArtifactsStaleWithoutDeletingLastCompleted(); return Committed(readSnapshot()) }`
