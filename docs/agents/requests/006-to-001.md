# Agent 006 → Agent 001: bind app operations to C6 for their full lifetime

- Requesting agent: 006
- Receiving agent: 001
- Source commit: `ba842ef5e22b58929426b6b39056ac15743f0fdb` plus C6 v2 lease-bound read follow-up on `agents/006-repository-boundaries`
- Target path/symbol: `app/src/main/java/com/realityforge/scanner/ScannerViewModel.kt`; capture/import/reconstruct/export/delete entry points and direct `repository.dao` mutations

## Problem / reproducer

The M19 busy flag is process-local. The ViewModel reads selected project state, suspends, then uses
direct DAO/files later. Agent 006 rejects conflicting C6 operations, but a complete reconstruction
or export must hold one request from initial immutable binding through final validation/publication.
The Agent 006 instrumentation regression proves an active C6 read rejects direct mutation on that
project while a second project remains independent.

## Agreed interface

Bind `projectId`, `revision`, canonical UUID `operationId` and, for reconstruction/publication,
`ProjectJobIdentity(jobId, attemptToken)` before suspension. Call
`ProjectRepository.withProjectAccess(ProjectOperationRequest, block)`. Inside an existing lease use
`repository.inputSnapshot(session)` or `repository.currentResult(session)`; do not call a
project-ID convenience overload that would acquire a nested reservation. Selection changes do not
cancel or retarget the bound request, and a session must never escape its block.

Minimal adapter shape:

```kotlin
val bound = OperationContext(projectId, revision, operationId, jobId, attemptToken)
repository.withProjectAccess(bound.toC6Request(ProjectOperationKind.RECONSTRUCT)) { session ->
    val snapshot = repository.inputSnapshot(session)
    pipeline.run(snapshot) // owner 002; publish through owner 023
}
```

## Affected tests

- delayed activity/capture/export callback cannot target a newly selected project;
- import/export/delete/reconstruct conflict matrix on one project;
- simultaneous operations on two projects;
- rotation/process recreation with durable job attempt;
- no session use after the reservation block returns.
