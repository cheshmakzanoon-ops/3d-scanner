# Agent 022 -> Agent 006: repository facade integration

Please make the public repository facade delegate permanent project/photo deletion to
`DeletionService`; remove direct `dao.deleteProject` + `File.deleteRecursively` behavior after the
adapter is integrated.

Required facade behavior:

- Create `DeletionIntent` with immutable project/photo identity and expected revision, then accept
  only an explicitly confirmed request from the UI/controller.
- Expose `PendingDeletion` and typed `DeletionRunResult` for retry/status. Cancel before
  confirmation does nothing; cancellation after confirmation leaves a recoverable tombstone.
- Bind Agent 005 persistence and Agent 007 lease coordination. Do not perform a second recursive
  delete or infer paths from filenames in the facade.
- Reject new imports/captures/reconstruction/exports/curation/publication once logical deletion
  commits. Existing admitted work must become a typed lease blocker or drain safely.
- Add facade integration tests proving two projects and an independent duplicate cannot delete
  one another, and a retryable cleanup remains visible after repository/process recreation.

The old `ProjectRepository.delete` must not remain a reachable alternate destructive path.
