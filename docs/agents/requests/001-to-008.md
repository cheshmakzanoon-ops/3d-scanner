## Problem and reproducer

The current baseline cancels the active ViewModel/native reconstruction whenever `MainActivity.onStop()` runs. Agent 001 intentionally preserved that conservative behavior because no verified durable C7 runner owns the job yet. Removing it before job acquisition, checkpoint, cancellation and process-recovery semantics are proven could leave work orphaned or publish partial/stale artifacts.

Reproducer for the missing integration:

1. Start reconstruction for project/revision A with a bound C1 `OperationContext`.
2. Rotate, background the activity, turn the screen off, remove the task, or let Android stop/timeout the execution component.
3. Reopen the app and inspect authoritative job state.
4. The same job identity must either remain safely active or resume from verified checkpoints; pause/cancel must address that exact job and partial outputs must not become current.

## Agreed interface, fields, units and lifetimes

The C7 runner adapter consumed by Agent 001 must carry, at minimum:

- opaque `operationId`, `jobId`, fixed `projectId`, fixed input `revision` and immutable input/artifact identity;
- explicit runner state (`QUEUED`, `RUNNING`, `PAUSING`, `PAUSED`, `CANCELLING`, `CANCELLED`, `SUCCEEDED`, `FAILED`, or equivalent C7 vocabulary);
- progress stage plus integer completed/total units where known;
- attempt/lease identity and lease expiry in epoch milliseconds or monotonic duration with the clock specified;
- typed pause/cancel/timeout/failure cause;
- checkpoint/artifact references that are verified before resume/publication;
- resource-release completion evidence for native operation tokens;
- a durable state stream/query that survives activity recreation and process restart within supported Android behavior.

Lifetimes and invariants:

- Activity/Composable lifetime must not own the job.
- A foreground service/worker instance may be replaced; durable `jobId` and attempt identity remain authoritative.
- `onStop` must not imply user cancellation once C7 is integrated.
- Force-stop is not survivable and must be documented honestly; restart may recover only persisted/checkpointed work.
- Only the current project revision/attempt may publish final artifacts. Cancellation/timeout must release the matching native token within a measured bound.
- Camera capture remains separate from CPU reconstruction lifecycle.

## Proposed minimal adapter

Agent 008 should expose a small application-facing port from its reserved package, for example:

```kotlin
interface ReconstructionExecutionController {
    val jobs: StateFlow<Map<JobId, JobSnapshot>>
    suspend fun enqueue(context: OperationContext, request: PipelineRequest): JobId
    suspend fun pause(jobId: JobId)
    suspend fun resume(jobId: JobId)
    suspend fun cancel(jobId: JobId)
}
```

`ScannerViewModel.reconstruct(...)` should submit the already-bound C1 context instead of owning the long-lived coroutine/native token. `ScannerViewModel.pause()` delegates by `jobId`. After Agent 008 proves lifecycle behavior, submit a return handoff to Agent 001 requesting the two owner edits:

```kotlin
// MainActivity.onStop(): no unconditional model.onHostStopped()
// ScannerViewModel.onHostStopped(): observe/detach UI only; do not cancel durable work
```

Do not directly edit Agent 001-owned files on the Agent 008 branch. Agent 001 will apply the final adapter change after the supplying C7 commit and tests are identified.
