## Problem and reproducer
A reconstruction can begin with one selected set, then curation can change while it runs. Sequential artifact writes and a revision-only completion check can expose stale or partial output as current.

## Interface
The job must carry `ReconstructionSelectionLease`. Immediately before the atomic current-result pointer swap, reload `PhotoCurationService.selectedPhotos(projectId)` and call `ReconstructionSelectionGuard.verifyPublication`. Publish only on `Current`; on `Stale`, retain the previous completed result and quarantine/delete the new partial generation. The publication transaction must bind project ID, project revision, selection fingerprint, ordered IDs, artifact identity, and all required files.

## Minimal adapter pseudocode
`write generation to private staging dir; fsync files/dir; current = curation.selectedPhotos(id); if guard(lease,current) is Stale -> discard staging; else compare-and-swap current manifest while retaining previous completed manifest`.

## Tests and verification
Curation changes at every publication fault point, reason-only metadata does not stale, selected/pending lifecycle changes do stale, crash recovery never exposes a partial generation, and old completed output remains reopenable.
