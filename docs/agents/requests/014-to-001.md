# Agent 014 → Agent 001: project-bound capture publication

- Requesting agent: **014 — Camera session identity, lifecycle and permission recovery**
- Receiving agent: **001 — Android application composition and operation ownership**
- Supplying source commit: `__SOURCE_SHA__`
- Target path/symbol: `app/src/main/java/com/realityforge/scanner/ScannerViewModel.kt`, replace or overload `captureReady(file: File)` with a request-bound publication entry point.

## Problem and reproducer

The existing `captureReady(file)` reads `selectedId.value` after CameraX completes. A delayed callback can therefore import a photograph into a project selected after the shutter press. Agent 014 now delivers `CapturedPhoto(projectId, revision, sessionToken, captureToken, stagedFile, metadata)` and rejects late callbacks only while the capture route owns them; application publication must preserve the same immutable identity.

Regression: open project A, start a capture through a controllable adapter, press Back, select project B, then release the delayed callback. Project B must remain unchanged and the staging file must be removed.

## Agreed interface, units and lifetime

- Input: the exact `CapturedPhoto` from Agent 014. `revision` is the expected project revision before this photograph commits; revisions are non-negative and monotonically advance after accepted mutations.
- Output: `CaptureCommitOutcome.Accepted(committedRevision)` only after the project-bound import transaction and durable original-file publication complete. `committedRevision` must be greater than `photo.revision`.
- Rejection: return `CaptureCommitOutcome.Rejected(reason)` for stale revision, missing project/session, duplicate, invalid input, cancellation before commit, or publication failure.
- Never consult `selectedId` to choose the destination.
- On `Accepted`, the publication path owns and removes the staging file after durable copy. On `Rejected`, leave the file for Agent 014 to delete.
- Associate the active application operation with `projectId + revision + sessionToken`; a different token cannot complete it.

## Minimal adapter sketch

```kotlin
suspend fun publishCapturedPhoto(photo: CapturedPhoto): CaptureCommitOutcome {
    val active = captureOperation.value
    if (active?.projectId != photo.projectId || active.sessionToken != photo.sessionToken) {
        return CaptureCommitOutcome.Rejected("Capture session is no longer active.")
    }
    return when (val result = repository.publishCapturedPhoto(photo)) {
        is CapturePublication.Accepted -> {
            photo.stagedFile.delete()
            CaptureCommitOutcome.Accepted(result.committedRevision)
        }
        is CapturePublication.Rejected -> CaptureCommitOutcome.Rejected(result.reason)
    }
}
```

The concrete repository result is coordinated with Agent 006; do not recreate destination selection inside the ViewModel.
