- **Receiving agent:** 071 — App shell, navigation and launcher plumbing
- **Source branch:** `agents/001-app-composition`

- **Supplying contract:** `docs/agents/contracts/001.md` (`C1/v1`)
- **Exact target path:** `app/src/main/java/com/realityforge/scanner/ui/ScannerApp.kt`
- **Exact target symbols:** `ScannerApp`; launchers `picker`, `checkerboardPicker`, `exportGlb`, `exportPly`, `exportMeshGlb`, `exportTexturedGlb`, `exportTexturePng`, `exportMeshPly`, `exportDenseGlb`, `exportDensePly`, `exportCapture`, `exportDiagnostics`; the `CameraScreen` `onClose`/`onPhoto` callbacks and every corresponding `launch(...)` action.

## Problem and reproducer

The existing launcher callbacks call compatibility methods such as `model.import(...)`, `model.captureReady(...)`, `model.calibrateLens(...)`, `model.export(...)`, and `model.exportCaptureBundle(...)`. A result can return after project selection changes or after activity recreation. If no request was bound before launch, those compatibility methods must fall back to the then-current selection, which does not satisfy C1.

Reproducer:

1. Select project A.
2. Open a picker, camera, or `CreateDocument` launcher.
3. Recreate the activity or navigate/select project B before the external result returns.
4. Return a successful result.
5. The completion must target only the project/revision/result that opened the request, exactly once; it must never infer project B from current UI selection.

Agent 001's coordinator and `SavedStateHandle` persistence already reject duplicate/stale completions and preserve the bound request across recreation. The remaining owner change is to bind at every launcher call site and pass the opaque ID back at completion.

## Agreed interface, fields, units and lifetimes

- `requestId: String` is opaque, non-empty and process-state-persisted by `ScannerViewModel`; do not parse it or derive a replacement.
- Project ID, project revision, selection generation, operation ID and creation time in epoch milliseconds are captured inside `begin*Request()` before the launcher suspends.
- Capture additionally owns one immutable session ID.
- Artifact export additionally binds `artifactKey`, `resultRevision` and the exact extension before `CreateDocument` opens.
- At most one external request is pending. A request is one-shot: complete it once or cancel it once.
- Keep the request ID in `rememberSaveable`, and reconcile it with `model.scannerState.pendingRequests` after activity recreation. Never bind a second request merely because the Composable was recreated.
- A null/cancelled picker or document result must call `model.cancelPendingRequest(requestId)`. A cancelled camera flow must also delete/abandon its temporary capture file through the existing camera owner path.
- Project selection may change while an external request is pending. Do not cancel a valid request solely because selection changed.

## Minimal adapter pseudocode

```kotlin
val scannerState by model.scannerState.collectAsStateWithLifecycle()
var importRequestId by rememberSaveable { mutableStateOf<String?>(null) }

LaunchedEffect(scannerState.pendingRequests) {
    importRequestId = scannerState.pendingRequests
        .singleOrNull { it.kind == OperationKind.IMPORT_PHOTOS }
        ?.requestId?.value
}

val picker = rememberLauncherForActivityResult(
    ActivityResultContracts.OpenMultipleDocuments(),
) { uris ->
    importRequestId?.let { requestId ->
        if (uris.isEmpty()) model.cancelPendingRequest(requestId)
        else model.completeImport(requestId, uris)
    }
    importRequestId = null
}

fun launchImport() {
    val requestId = model.beginImportRequest() ?: return
    importRequestId = requestId
    picker.launch(arrayOf("image/jpeg", "image/png", "image/webp", "image/heic", "image/heif"))
}
```

Apply the same pattern with:

- `beginCaptureRequest()` → `completeCapture(requestId, file)`; cancel on `CameraScreen.onClose`.
- `beginCalibrationRequest()` → `completeCalibration(requestId, uris)`.
- `beginCaptureBundleExportRequest()` → `completeCaptureBundleExport(requestId, uri)`.
- `beginArtifactExportRequest(extension)` → `completeArtifactExport(requestId, uri)` for every listed extension.

Prefer a small reusable launcher-state adapter keyed by `OperationKind` rather than duplicating divergent request logic. Keep all repository and operation execution in Agent 001's ViewModel; Agent 071 owns only route/launcher plumbing.
