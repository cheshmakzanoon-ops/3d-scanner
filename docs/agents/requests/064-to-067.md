# Agent 064 → Agent 067: typed export materialization

Source branch/commit: see final `docs/agents/status/064.md`; contract at `docs/agents/contracts/064.md`. Exact target is Agent 067 ExportCoordinator's native materializer adapter. Consume C10 immutable asset views and the public `ply_export.hpp` API. No current project artifact is opened or overwritten.

`describePly` reports exact total bytes, vertex stride and optional attributes. `writePly` supports binary little-endian (default) and ASCII. Stable property order/types are double xyz, optional double normals, uchar RGB, float confidence, uint supporting_views, then triangle face list uchar/uint vertex_indices. Sparse and dense labels differ. A photographic source surface exports as observed_surface with an explicit texture-omitted comment, never photographic appearance. Unknown units remain arbitrary in metadata. All fields, counts, faces and output budgets are validated before emission. Generic readers need not understand custom evidence comments/properties.


Materialize only into private staging streams, retain the returned descriptor/report and close files, then validate and transport via 026. Errors/cancellation/short writes/flush failure must abort the entire export. For multi-file OBJ, archive every descriptor filename at ZIP root, forbid renamed/missing siblings and validate references after extraction. Expected regression: changed selected project while a pending export picker returns cannot change the immutable request's artifact/revision, and any failed transport is not success.
