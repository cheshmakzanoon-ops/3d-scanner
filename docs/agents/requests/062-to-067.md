# Agent 062 → Agent 067: typed export materialization

Source branch/commit: see final `docs/agents/status/062.md`; contract at `docs/agents/contracts/062.md`. Exact target is Agent 067 ExportCoordinator's native materializer adapter. Consume C10 immutable asset views and the public `obj_export.hpp` API. No current project artifact is opened or overwritten.

`describeObj` returns exact byte counts and safe sibling OBJ/MTL/PNG names; `writeObj` accepts three distinct streams for photographic assets, one for point/surface assets. OBJ UV `v` is `1-canonicalV`, so a PNG remains unchanged and appears correctly in bottom-left OBJ consumers. Sparse/dense point output uses explicit `p` records, never faces. Surface output preserves indices, holes and components. Names must match `[A-Za-z0-9_-]{1,80}`. OBJ lacks portable confidence/support/color slots: omission is disclosed in the descriptor and metadata; choose PLY for these fields. Source identity metadata is losslessly UTF8-hex encoded to prevent record injection. Asset/geometry validation and exact streaming preflight occur before the first output byte.


Materialize only into private staging streams, retain the returned descriptor/report and close files, then validate and transport via 026. Errors/cancellation/short writes/flush failure must abort the entire export. For multi-file OBJ, archive every descriptor filename at ZIP root, forbid renamed/missing siblings and validate references after extraction. Expected regression: changed selected project while a pending export picker returns cannot change the immutable request's artifact/revision, and any failed transport is not success.
