# Agent 007 → Agent 074: render durable job snapshots without inventing progress

- **Requesting agent:** 007 — Persistent reconstruction jobs and recovery ledger
- **Receiving agent:** 074 — Processing progress, pause and recovery screen
- **Source commit:** `4460d56109d8f6dae637996b645549e4490fa79b`
- **Target owner path/symbols:** `app/src/main/java/com/realityforge/scanner/ui/processing/`; `JobUiState` adapter and `JobAction`

## Problem and reproducer

The current UI exposes process-local progress. Agent 007 persists bounded coarse progress and terminal/interruption truth. It intentionally has no pixel-level unit and may have unknown totals; the screen must not fabricate percentages or operate on the currently selected job by accident.

## Agreed interface

Map `JobSnapshot` as follows:

- `QUEUED`, `RUNNING`, `PAUSED`, `FAILED`, `CANCELLED`, `COMPLETED`, `STALE`, and `BLOCKED_EXTERNAL` remain distinct UI states;
- `JobProgress.totalUnits == null` means indeterminate; do not derive a percentage or ETA;
- show stage and coarse unit values exactly as stored; event history is bounded and not an audit log of every inner-loop update;
- preserve and display immutable project revision/input/engine identity where technical details are requested;
- enable pause only for queued/running, resume only for paused, retry only for failed/blocked, and cancel only for nonterminal work, while accepting idempotent command dispositions;
- actions carry the displayed stable `JobId`, never a current-selection lookup;
- stale/cancelled/failed jobs do not imply the prior completed result was deleted; Agent 023 owns that presentation link.

## Minimal adapter pseudocode

```kotlin
fun JobSnapshot.toUiState(): JobUiState = JobUiState(
    jobId = jobId,
    status = state,
    stage = cursor.acceptedStage,
    progress = progress?.let { if (it.totalUnits == null) Indeterminate(it) else Determinate(it) },
    availableActions = actionsFor(state),
)
```
