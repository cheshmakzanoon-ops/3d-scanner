## Problem and reproducer

Agent 026's deterministic unit store covers transfer-state behavior, but the assignment requires
a real Android `DocumentsProvider` fault matrix. The roster assigns the only test provider and
manifest registration to Agent 088; Agent 026 must not ship or register a competing provider.

## Required provider controls

Expose per-test configuration, isolated by authority/document/request ID, for:

- short/truncated writes that close without throwing;
- permission revocation before open and during verification;
- missing/unavailable document;
- `ENOSPC`/quota failure after a configured byte count;
- readable exact bytes, size-only metadata, and no-verification capabilities;
- deletion success/failure for newly-created documents;
- a pre-existing document whose delete call is recorded and must remain zero; and
- optional temporary-document commit/abort when genuinely implemented.

The process controller should support killing/restarting the client around an active transfer
without treating process death as success. Provider state and call logs must be queryable by
instrumentation after restart.

## Agent 026 scenarios to consume it

Run `DestinationTransferService` against the shared provider and assert typed outcome, exact
bytes/hash, bytes copied, cleanup disposition, delete-call ownership and provider atomicity.
No provider helper should be included in the release manifest/source set.
