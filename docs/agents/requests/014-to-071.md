# Agent 014 → Agent 071: immutable camera-route composition

- Requesting agent: **014 — Camera session identity, lifecycle and permission recovery**
- Receiving agent: **071 — Scanner application navigation and screen composition**
- Supplying source commit: `__SOURCE_SHA__`
- Target path/symbol: `app/src/main/java/com/realityforge/scanner/ui/ScannerApp.kt`, camera route/navigation state and `CameraScreen` call site.

## Problem and reproducer

The current route calls the legacy `CameraScreen(onPhoto: (File) -> Unit)` and can close while CameraX is completing. The destination is later inferred by `ScannerViewModel.captureReady`, so changing selection between shutter and callback can import into the wrong project. Agent 014 provides an identity-bound continuous overload; it must receive a snapshot created before navigation.

Regression: select project A at revision N, enter camera, trigger a delayed shot, press Back, select project B, then complete the callback. Project B stays unchanged and the old staging file is removed.

## Agreed interface, units and lifetime

- Before opening the camera, snapshot `projectId` and current project revision and create one opaque `sessionToken`.
- Save/restore that exact `CaptureSessionIdentity`; never reconstruct it from the current selection after navigation or process recreation.
- Invoke the identity-bound overload:
  `CameraScreen(session, onClose: (CaptureCloseReason) -> Unit, onPhoto: suspend (CapturedPhoto) -> CaptureCommitOutcome, ...)`.
- Keep the route open after each accepted shot so the same token can capture repeatedly; committed revision advances through the returned outcome.
- On explicit Back/navigation/project deletion, close the route once. A later callback belongs to the old controller and cannot reopen or redirect navigation.
- Permission denial/camera-unavailable screens retain access to the existing photo-import flow.

## Minimal adapter sketch

```kotlin
val route = rememberSaveable(stateSaver = CaptureRouteSaver) {
    CaptureRoute(projectId = selected.id, revision = selected.revision, sessionToken = UUID.randomUUID().toString())
}
CameraScreen(
    session = CaptureSessionIdentity(route.projectId, route.revision, route.sessionToken),
    onClose = { reason -> closeCameraRoute(route.sessionToken, reason) },
    onPhoto = viewModel::publishCapturedPhoto,
)
```

The saved route must validate that its project still exists; invalid restored routes close without rebinding to a replacement selection.

## Affected tests

- delayed callback after Back/project selection change
- repeated photos remain in one route and advance revisions
- process recreation/rotation restores stable identity and committed count
- project deletion/revocation closes the old route
- system Back works while CameraX is capturing/committing
