## Original literal gaps

Notification mappers/intents were disconnected from the real service. Duplicate START, pause/cancel draining and old generations could leave stuck foreground lifetime or inaccurate restored progress.

## Implemented behavior and integration

The real service posts the private generic foreground notification synchronously, then waits for Room recovery and serializes immutable job/attempt commands. Duplicate starts preserve progress; pause/cancel do not start workers; stale commands cannot replace another job. Pending commands prevent premature stop, and an independent idle scope awaits the old worker before draining/stopping. One observer maps actual persisted job progress/terminal states. Running updates use rate gating; tagged paused/completed states survive foreground removal and cancellation removes alerts. Startup restoration queries authoritative execution_jobs, restores durable paused/relevant terminal states, and neither invents running work nor resurrects dismissed completion. Denied notification permission suppresses drawer posting while retaining foreground obligations and in-app controls.
