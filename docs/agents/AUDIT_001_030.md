# Agents 001–030 implementation audit

Audit date: 2026-10-20. Requested repository: `cheshmakzanoon-ops/3d-scanner`.
Campaign baseline: `ad3029193f304c70931b94ea7a0df90b69d84b07`.

## What was wrong at the start

All thirty numbered branches existed, but none of their work had been integrated into
the campaign baseline on `main`. Branches 003, 008, 011, 021, 024, 025 and 028 contained no
implementation beyond the baseline. Other branches ranged from useful isolated contracts
to substantial components whose actual application adapters were missing. An isolated
unit test, a status receipt or a handoff request was not treated as completed integration.

The integration preserves the functional histories of the twenty-three nonempty numbered
branches. The temporary `agents/030-bootstrap-upload` transport branch is not product code
and is not included. No numbered branch is deleted or force-pushed.

## Review method

Each group checked the shared working agreement and its exact sections in
[PRODUCTION_100_AGENT_EXECUTION_PLAN.md](../../PRODUCTION_100_AGENT_EXECUTION_PLAN.md),
then traced the actual UI, repository, Room, execution, native and filesystem call paths.
The work distinguishes three forms of evidence:

1. **Implementation:** executable production code and actual callers, with immutable
   project/revision/request/attempt identity where required.
2. **Executed verification:** an actual compiler, test, device or CI result for the stated
   candidate. A test that was merely added remains unexecuted until its real run succeeds.
3. **External qualification:** physical camera, process-lifecycle, thermal, large-profile,
   ARM64 and release-signing evidence. Those gates cannot be inferred from source review
   or synthetic fixtures.

Detailed requirement-by-requirement reviews are in:

- [Agents 001–010](audit/001-010.md)
- [Agents 011–020](audit/011-020.md)
- [Agents 021–030](audit/021-030.md)
- [Build foundation, agent 004](status/004.md)

Individual `status/NNN.md` receipts record each assignment's actual boundary. Local
implementation checkpoint hashes are local audit references, not claims that GitHub has
published those exact commit objects. The final integration commit and its CI source SHA
are the authoritative published candidate.

## Gates that must stay honest

The 30/100/250-photo target profiles are not advertised as supported until their algorithm,
resource and actual-device gates pass together. The current bounded profile must reject
unsupported requests clearly, as agent 002 explicitly permits. No stock mesh, synthetic
coverage, generated texture or fabricated successful stage fills missing reconstruction.

Physical camera vendors, session/background behavior, process-kill/upgrade protocols,
device thermal/RSS/large-profile benchmarks, Windows/macOS builds when unavailable, ARM64
release qualification, R8/JNI shrinking and signing are not proven by a host pass. Remaining
physical/release prerequisites are listed in the detailed receipts; an unrun gate is not DONE.

The source checksum manifest is regenerated from the staged Git blobs using
`build-logic/update_source_manifest.py`, with an exact tracked-file-set check. Generated
SDKs/toolchains/build outputs are excluded from the repository.
