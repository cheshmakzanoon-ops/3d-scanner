# C10 canonical assets v1

`realityforge/asset_model.hpp` defines non-owning `rf::asset` PointAsset,
SurfaceAsset and TexturedAsset views. Attribute and encoded-image lifetimes must
outlive validation/export; callers must prevent concurrent mutation. Views never
own or copy geometry. Source adapters must explicitly budget any required
repacking of legacy interleaved vertices; no copying happens in the serializer.

SparsePoints and DensePoints are distinct from ObservedSurface and
PhotographicSurface. Attribute counts must match vertices. Surface indices are
flat zero-based triples. Supplied normals must be finite unit vectors. Triangle
indices and area, UVs, confidence and PNG chunks are checked before output.
Textured assets require actual embedded RGBA/RGB PNG, normals and upper-left UVs.
Units are Arbitrary or Meters; selecting Meters requires the caller's independent
measurement provenance, never an exporter guess. Provenance IDs are UTF-8 and
sourceSha256, when supplied, is a lowercase 64-character digest.

`glb_export.hpp` offers stream and atomic-path overloads for all three views,
Limits and cooperative Cancel callbacks. Internal right/down/forward coordinates
are transformed by `diag(1,-1,-1)` into glTF right/up/back. This is a proper
rotation (determinant +1): triangle winding stays unchanged; normals receive the
same transform and UVs stay unchanged. Vertex colors never claim photographic
UV texture. glTF uses KHR_materials_unlit for faithful photographed/color display.
Original geometry and encoded PNG bytes remain unchanged.

No JNI, legacy writer or shared-build source is changed by this module. The
requests to 003/004/037/053/057 describe required integration. Until their actual
adapters land, new export module availability does not make the legacy labels
correct or make Android invoke these serializers.

Limits are checked before output/large allocation. GLB output streams binary
attributes rather than creating a second mesh/image buffer. File exports create
an exclusive sibling, flush/fsync/close, then atomically rename on success; failures
remove the temporary file and preserve an existing target. This provides atomic
file replacement, not a claim of parent-directory power-loss durability. Caller
owns artifact identity, destination authorization and final project publication.
