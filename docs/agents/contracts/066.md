# C11 versioned edit and measurement recipe

The C++ `asset_edit.hpp` API consumes Agent 061 C10 views. `applyEdits` validates
immutable parent identity and SHA-256 before creating a derived geometry owner.
`surface()` spans expire with that owner. `EditRecipe` version 1 supports, in
sequence, rigid row-major affine orientation (reflection supported), conservative
whole-triangle crop, connected-component selection and an explicit user-provided
known-distance reference. Arbitrary affine scaling/shear is rejected: metric
conversion must preserve its known-distance evidence. Orientation uses the same
internal x-right/y-down/z-forward coordinates as the source. Reflection transforms
normals and reverses triangle winding. Crop never cuts/caps/fills a triangle or
invented backside; it keeps only wholly contained faces. Original face orientation,
UV correspondence, colors and observed attributes survive compaction.

Component IDs are numbered by first referenced vertex in ascending index order
on the current recipe stage, including any earlier crop. Selection does not weld
vertices or join disconnected components. Empty results, invalid identities,
unknown versions, nonfinite transforms/UVs, invalid scale and cancellation throw
without changing the source. Input limits and a maximum of 256 operations bound
work; each large loop observes cancellation.

`MetricReferenceEdit` start/end are picked in the current edited coordinate frame;
`knownMeters`, `uncertaintyMeters` and a nonempty label must describe an actual
known-distance reference. The test fixtures are explicitly synthetic. Accepted
scale is baked into output positions, and output units become `Meters`.
`MeasurementEvidence.metersPerOriginalUnit` records the cumulative conversion for
provenance; exporters **must not multiply it into already converted output again**.
Relative uncertainty describes only the supplied reference, not unknown
reconstruction error or guaranteed physical accuracy. Unknown input scale stays
`Arbitrary`; `measureDistance` returns arbitrary units with no meter uncertainty.
A metric source without an explicit reference retains meters but reports unknown
uncertainty. This module makes no claim of independently calibrated accuracy.

The Kotlin `studio.editing.EditController` mirrors these operations and supplies
immutable snapshots, undo/redo, branching-history replacement and reopen. `save()`
returns a bounded 128 KiB RFE1 history with SHA-256 checksum. `restore()` rejects
unknown versions, truncation, corrupt hashes, unknown operation tags, invalid
values and trailing data; it restores both the undo cursor and redo operations.
This is an opaque recipe blob for owner 005, not a second database or a replacement
for owner 009 identities. The controller does not call reconstruction or mutate
any source asset. Owner 070 consumes it through edit action providers.

Result provenance retains parent/source, changes algorithm to `rf-asset-edit-v1`
and clears derived `assetId`. Owner 009 assigns a canonical descendant identity
from the complete recipe and source; owner 005 persists a recipe against the
unchanged parent; 003 exposes materialization through JNI; 067 exports the selected
materialized result. No cache hit or successful publication can be inferred from
a recipe/controller alone.
