# Library UI contract v1

`ui.library.LibraryScreen(LibraryUiState,onAction,modifier,onQueryChange?)` uses stable project IDs and restores search/sort/filter/list position. `LibraryProject.from(ScanProject)` is the honest baseline adapter. Create/open/delete callbacks carry the displayed identity; rename/duplicate/restore stay absent unless their real service is installed. Destructive confirmation stays scoped to the displayed project and revision.

`LibraryPresenter(ProjectLibraryService,failureMessage)` / `LibraryServiceScreen` consume Agent019 at `c88fc09fb9605aba08fef07f83514bddcd3342b8`. Queries are100-row pages; stale response/cancellation tickets cannot replace a newer query. Rename uses expected revision. Duplicate uses the real service’s independently copied/hash-verified originals and byte progress. Duplicate names are user supplied. No production test port, SQL or filesystem repository is implemented in UI.005/006 must supply `ProjectLibraryPort` and001 must expose the provider before071 enables this path.

Locale-independent search/name order, Unicode code-point name limits,10,000-item stable IDs and cancellation are tested. A lazy list avoids decoding/project-wide layout. Physical frame budgets, TalkBack, keyboard and200% font review are separate acceptance gates. Feature resources use `a072_` and no theme is duplicated.
