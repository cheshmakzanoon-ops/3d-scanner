The `export` package implements immutable project/revision/artifact/checksum requests,
a real-file catalog, private validation before transport, cancellation and bounded
staging, relocatable ZIP file sets, and a checksummed process-persistent pending
picker envelope. Calls run on an IO dispatcher. No choice reruns reconstruction.
`ExportSource` supplies current identity, actual available options, materialization
and format validation; native writers register only after their real adapter and
independent reader gate pass. `ExportDestination` is supplied by 026: `open`,
`commit`, `abort`. A failed cleanup explicitly reports a possibly partial document.
The current repository adapter excludes dense legacy GLB/PLY because their native
writer mislabels them sparse. OBJ/STL/LOD/edit variants are unavailable until their
native boundary and materializers are registered. This is deliberate fail-closed
eligibility, not a claim those serializers are integrated in the app.

Pending picker state is local, bounded, versioned and checksummed; restoration does
not launch work. A mismatched request cannot clear another pending picker. Source
revision is checked before staging, after validation and before commit. A provider
requires the 026 transaction/cleanup contract; an OutputStream alone cannot prove
atomic publication. Store uses private files and fsync before rename; full
power-loss filesystem/directory durability remains a storage-owner gate.

Existing-file options bind the exact content SHA256 in addition to metadata/project
identity. Same-length artifact replacement cannot alter a pending export silently.
Pending picker schema2 requires that content identity. Unhashed schema1 envelopes
are explicitly rejected and preserved for user-directed quarantine/reselection,
never silently upgraded with current mutable file bytes.
