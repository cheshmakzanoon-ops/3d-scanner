## Identity and lifetime

Every operation has a unique `OperationId` and `JobId`. Every external activity result has a one-use `RequestId`; capture also has a stable `SessionId`. Project-bound work carries an immutable `ProjectRevision(projectId, revision)` captured synchronously before a launcher or coroutine can suspend.

A pending external request begins when the UI calls one of the `begin*Request` methods and ends when its exact request ID is completed or cancelled. Pending request identity is versioned and persisted through `SavedStateHandle`. Completion never reads `selectedId` to choose a destination. A changed project revision rejects the stale request before mutation or source transfer.

Only one operation or external request is admitted by the current compatible foundation. Selection may change while a picker/camera request is pending, but selection does not cancel that request and cannot redirect it. Direct work is rejected until the pending request is completed or explicitly cancelled.

## Public ViewModel adapter

The safe launcher protocol is:

```text
requestId = beginImportRequest()
completeImport(requestId, uris) / cancelPendingRequest(requestId)

requestId = beginCaptureRequest()
completeCapture(requestId, stagedFile) / cancelPendingRequest(requestId)

requestId = beginCalibrationRequest()
completeCalibration(requestId, uris) / cancelPendingRequest(requestId)

requestId = beginCaptureBundleExportRequest()
completeCaptureBundleExport(requestId, destinationUri) / cancelPendingRequest(requestId)

requestId = beginArtifactExportRequest(extension)
completeArtifactExport(requestId, destinationUri) / cancelPendingRequest(requestId)
```

`scannerState` is immutable and includes selected project/revision, selection generation, active operation, pending request summaries, typed progress, preview/calibration state, and a presentation message code plus fallback text. Existing mutable flows and callback methods remain as compatibility adapters until Agent 071 migrates `ScannerApp.kt`; they consume an already-bound pending request when one exists.

## Invariants

1. External completion is one-use and kind-checked.
2. Project mutation validates the bound revision before the first mutation.
3. Artifact export binds project, project revision, result revision, artifact key and extension before the destination picker opens, then rechecks them after transfer.
4. A stale operation finalizer cannot clear another operation's ownership.
5. Reconstruction remains activity-owned and is cancelled on host stop until Agent 008 supplies and verifies C7 durable execution. No background-service claim is made by C1/v1.
6. User-facing errors cross the presentation boundary as a stable code, fallback text and arguments; Agent 078 may localize them without changing operation semantics.

## Batch note

C1/v1 preserves the existing batch import behavior after one initial revision check. Multi-shot capture admission, where each successful photo advances the expected revision while retaining one capture session identity, remains an Agent 014/C5 integration and must not be implemented by weakening fixed-revision artifact checks.
