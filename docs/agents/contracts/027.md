# Agent 027 — Lens calibration workflow contract

## Ownership

Agent 027 owns the offline checkerboard calibration engine, its versioned profile/evidence model, and the workflow-facing publication abstraction. This branch intentionally does not edit the application controller, repository/database, capture metadata, LensGeometry mathematics, or UI packages owned by Agents 001, 005/006, 013, 031, 073 and 075.

## Public production interfaces

### `LensCalibration.calculateSession`

```kotlin
suspend fun calculateSession(
    context: Context,
    inputs: List<CalibrationImageInput>,
    progress: (CalibrationSessionProgress) -> Unit = {},
): CalibrationSessionResult
```

- Accepts 10–40 immutable `CalibrationImageInput` values.
- Copies every document-provider stream into a bounded private temporary file, computes SHA-256 while copying, and optionally verifies the caller-bound expected digest.
- Never persists a raw URI or document-provider path.
- Releases the source stream, temporary file, bitmap, and every OpenCV `Mat` on success, rejection, exception, or coroutine cancellation.
- Returns `Success(CalibrationProfileRecord)` or a typed `Rejected` result. Cancellation is propagated as `CancellationException`; it is not converted into a success or a numerical failure.
- The existing `calculate(Context, List<Uri>, progress)` entry point remains source-compatible and delegates to this method. Its `LensProfile` result is an aggregate compatibility adapter and cannot carry complete per-view evidence.

### Evidence and rejection semantics

`CalibrationSetEvaluator` is pure and deterministic. It records each selected view as accepted or rejected with one concrete reason. It enforces:

- all 9×6 inner corners,
- board area in `[0.018, 0.90]` of the upright analysis image,
- a dominant upright dimension/crop group,
- dominant camera/lens/crop/orientation identity when supplied,
- at most 8% focal-length spread and 5% zoom-ratio spread,
- at least 10 compatible accepted views,
- x-center range at least 0.12, y-center range at least 0.10, and board-area ratio at least 1.25.

Unsupported optical mixtures and low viewpoint diversity are separate from `NUMERIC_CONVERGENCE_FAILED`. Missing metadata remains explicit unverified evidence and never proves compatibility.

### Profile schema

`CalibrationProfileCodec` writes bounded schema 2 JSON and reads both schema 1 and schema 2. The on-disk filename remains `camera-calibration-v1.json` until its repository owner changes that external contract.

Schema 2 includes:

- Brown–Conrady intrinsics/distortion and global RMS,
- canonical `cal-v2-<sha256>` content identity independent of JSON key iteration order,
- source-set digest when all accepted input hashes are known,
- evidence source (`physical_device`, `emulator`, `synthetic`, user-selected unverified, or legacy unverified),
- explicit physical same-lens verification flag,
- aggregate compatibility metadata,
- measured coverage and per-view acceptance/rejection evidence,
- per-view reprojection RMS for accepted views.

Encoded profiles are capped at 10,000 bytes to remain compatible with the current repository reader. Legacy schema-1 imports are always labeled `legacy_unverified`; they are never upgraded to physical evidence.

### Compatibility

`CalibrationProfileCompatibility.evaluate(record, capture)` returns:

- `VERIFIED_COMPATIBLE` only when dimensions/aspect and all optical identity fields match and the stored profile is explicitly physical same-lens evidence,
- `COMPATIBLE_WITH_UNVERIFIED_METADATA` when no known field conflicts but required identity evidence is absent,
- `INCOMPATIBLE` with concrete aspect/crop/camera/lens/zoom/orientation/focal reasons when a known field conflicts.

Agent 031 remains the owner of projection and distortion math. This contract does not change `LensProfile.forScan`; it supplies a more inspectable preflight decision for controller and diagnostics owners.

### Publication lifecycle

`ProfileStore` and `CalibrationProfilePublicationPort` define the owner-023 transaction boundary:

1. Controller binds `CalibrationOperationKey(projectId, expectedRevision, operationId)` before launching a picker or worker.
2. `TransactionalProfileStore` canonicalizes and decodes a save payload before staging it.
3. The publication port stages save/remove work without exposing it as current.
4. `commit()` must compare the expected project revision, atomically publish the profile mutation and result invalidation, advance revision, and return a terminal result.
5. Cancellation or exception after staging invokes idempotent `abort()` in `NonCancellable` context.
6. A save result is rejected if the committed profile identity differs or the revision did not advance.

No implementation may invalidate the current project result before a replacement profile is durably publishable, and a stale picker callback must return `Stale`, not mutate the newly selected project.

- Agent 006: expose profile reads through the repository facade without bypassing schema validation.
- Agent 009: include `profileId`/source identity in downstream artifact identity.

- Agent 012: replace direct decode with owned-image contracts when available while preserving the release guarantees above.
- Agent 013: populate camera/lens/zoom/crop/orientation identity and evidence source.
- Agent 021: retain the 42 MB per-input and 10 KB profile bounds in storage policy.
- Agent 023: implement the staged, revision-bound atomic publication port.
- Agent 031: consume compatibility results before projection and retain existing Brown–Conrady conventions.
- Agents 073/075: render measured coverage, rejected-view guidance, and same-lens instructions from typed state.

## Verification boundary

Local source verification in this branch covers Kotlin compilation against Android/OpenCV interfaces and deterministic pure-policy smoke execution. Repository Android unit/lint/assemble jobs must run in CI. Emulator instrumentation and physical same-lens handset capture remain distinct gates; neither may be inferred from JVM, synthetic, or emulator evidence.
