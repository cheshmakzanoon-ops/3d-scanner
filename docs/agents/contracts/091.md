# Candidate validation interface v1

`python tools/check_apk.py APK --release --signing-mode test --report REPORT`
verifies merged manifest privacy/backup flags, exact six-library × two-ABI inventory,
16KB ELF LOAD and ZIP alignment, modern APK signing, SHA256/version/signing identity.
`--require-notices` adds the required attribution gate. `--certificate-sha256 HEX`
is mandatory with production mode. No signature bypass exists.

`python tools/release/package_validation/bundle.py AAB --bundletool JAR --output DIR
--keystore FILE --key-alias ALIAS --store-pass-file FILE --key-pass-file FILE`
requires bundletool1.18.2 SHA256
378b5434cd1378bef6b2bc527b8c7f0ff2584b273830335bce54d6d0813c8584,
validates AAB then signs/audits universal and delivered split APKs. It records
AAB/tool/split hashes and certificate digests. Passwords use private temporary files.

`candidate.py` additionally requires notices, minification mapping and native symbols.
Manual candidate workflow builds and optionally runs minified correctness on API35.
Production publishing is outside this interface. Device installation/runtime evidence
must accompany package reports; compiler/package success alone does not establish it.

Build integration uses render_convention.py to inline exact convention imports/body into the owner build file. AGP8.11.1 applied Kotlin script lint crashes were observed and retained; the inline form preserves the default analyzer and all lint gates.

Instrumentation defaults to debug. Release build invocations must pass
`-PrealityForgeTestBuildType=release` when requesting `assembleReleaseAndroidTest`;
the selector accepts only `debug` or `release`. Both configurations use the same
committed source and approved dependency lock. This preserves debug CI while the
release candidate remains non-debuggable, shrunk and minified.
