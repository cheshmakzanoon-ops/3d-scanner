# Evidence-based dense selection

C++ `rf::detail::selectDenseEvidence` and Kotlin `DenseViewSelection.select` consume stable photo IDs, finite world camera centres (arbitrary shared units), deduplicated verified stable sparse-track IDs, measured normalized sharpness, and texture availability. They return ordered reference IDs, per-reference source adjacency, sparse-track union count and explicit exclusion reasons. Set-cover prioritizes newly observed sparse tracks; source candidates require independent verified track overlap and nonzero baseline. Candidate overlap is never reported as actual dense support or complete-object coverage. Caps:250 cameras,500000 total track observations,20000 tracks/camera,8 references,3 sources. Cancellation leaves no partial plan. Source memberships are selected separately from reference membership: executor must map source IDs to active working sets without truncating silently.

Existing `denseSourcePlan` retains <=4 baseline behavior and uses canonical pose ordering for equal geometric scores. 046 consumes the evidence API and uses actual depth reciprocal gates; 030 supplies admission caps; 002 owns coordinator wiring.
