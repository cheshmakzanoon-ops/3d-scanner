# Evidence-based dense selection

C++ `rf::detail::selectDenseEvidence` and Kotlin `DenseViewSelection.select` consume stable photo IDs, finite world camera centres (arbitrary shared units), deduplicated verified sparse-track IDs (full SHA256 strings in Kotlin; explicitly mapped compact-native IDs in C++), measured normalized sharpness, and texture availability. They return ordered reference IDs, per-reference source adjacency, sparse-track union count and explicit exclusion reasons. Set-cover prioritizes newly observed sparse tracks; source candidates require independent verified track overlap and nonzero baseline. Candidate overlap is never reported as actual dense support or complete-object coverage. Caps:250 cameras,500000 total track observations,20000 tracks/camera,8 references,3 sources. Cancellation leaves no partial plan. Source IDs are restricted to the admitted reference set; no additional decoded cameras are hidden in adjacency. Selected references form one connected verified component; other components remain explicitly excluded.

Existing `denseSourcePlan` retains <=4 baseline behavior and uses canonical pose ordering for equal geometric scores. 046 consumes the evidence API and uses actual depth reciprocal gates; 030 supplies admission caps; 002 owns coordinator wiring.

036 stable source identities are never truncated to Long. Native planner is one compact window with caller-retained bijection to full source strings; do not persist compact IDs. Kotlin camera evidence and returned plans snapshot mutable collections defensively.
