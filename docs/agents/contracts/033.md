# Agent 033: Feature cache integrity and eviction

FeatureCache(root,byteBudget).load(identity) returns Hit(CachedFeatures) or Miss(reason); store(record) returns false on IO/budget failure, never scan success. Identity includes original SHA256, decoder transform, extractor settings and OpenCV version. RF feature binary version2 has bounded exact payload, SHA256, image/count/128-column shape and validated coordinates/descriptors. Atomic unique temporary writes and hash-name-only byte eviction preserve unrelated files. CachedFeatures is a copied DTO with float[count*2], ARGB[count], float[count*128]; construct Mats only after validated Hit, release on conversion failure. Unsupported old binary is a recompute miss; there is no permissive legacy parser.

All pixel/ray conventions follow031: x-right/y-down/z-forward, arbitrary world scale. This implementation does not itself admit larger reconstruction profiles or claim physical-device qualification. Combined coordinator wiring and actual runtime fixture evidence remain separately recorded gates.

All publication/eviction/invalidation transactions now acquire one of64bounded JVM lockstripes and an exclusive `.feature-cache.lock` OS file lease, opened with NOFOLLOW. Lock acquisition is bounded (up to500ms local plus500ms crossprocess); busy/unavailable cache means safe false/miss. Reads stay unlocked against immutable opened-file snapshots. Failed eviction rolls back the newly published cache entry. Tests hold the actual reserved file lock and prove that a second instance cannot publish or invalidate during that lease, then stress independent writers under one byte budget.
