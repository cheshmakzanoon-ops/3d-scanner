# Agent 036 — source-bound tracks and explicit native windows

`MultiViewTrackGraph` retains legacy snapshot/packedRows for existing <=12-camera callers, and admits at most250 source views with1000000 graph nodes. A larger graph must use `nativeBatches`; the old native row API refuses an oversized camera set. Batches contain complete tracks, <=12 cameras, <=100000 observations, and explicit local-to-source camera and track mappings. Tracks that individually exceed a declared native window fail explicitly rather than being silently truncated.

`stableSnapshot(photoIds)` requires unique source-photo identities, independent of camera ordering. Each source-observation identity is SHA256(observation-v1, source photo, original keypoint). A track's canonical ID is the minimum observation identity; every observation aliases that canonical ID. A merger can choose a smaller canonical ID, while old published canonical IDs still resolve through `TrackSnapshot.resolve`; identifiers are never recycled as array ordinals. Consumers must persist source observation provenance, not only compact rows.

TrackSnapshot schema1 uses bounded exact-length UTF-8 records with whole-payload SHA256. Readers reject unknown versions, checksum mismatch, trailing bytes, duplicate observations/photos/IDs and all count/allocation-budget violations. Schema upgrades require explicit migration or recompute. Serialized payload is capped below64MB; identity-format changes require stage invalidation through009.

Rejected graph edges retain INVALID_RAY, EPIPOLAR, SAME_PHOTO_CONFLICT or NODE_BUDGET evidence. Cameras must have finite rigid proper rotations; bad feature rays cannot sneak into partial native tracks. JVM fixtures cover source-order permutations, checksummed resume, malformed input and250-photo bounded packing. Phone memory and production JNI remain separate measured gates.

`nativeSnapshot(photoIds,maxTracks)` is the exact <=12-camera compatibility adapter: it preserves original camera order and the identical complete-track order used by legacy packedRows, with full canonical source SHA IDs for each compact track ordinal. Do not zip the SHA-sorted durable snapshot against legacy packed rows. Empty track metadata is a valid empty transfer batch and never a completed reconstruction; consumers must enforce their native minimum-support gate. Graph mutations and snapshot/packing methods share one monitor so mappings cannot tear across concurrent additions.
