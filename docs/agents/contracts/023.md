# Agent 023 contract — atomic artifact-set publication

Branch: `agents/023-atomic-result-publication`
Campaign base: `ad3029193f304c70931b94ea7a0df90b69d84b07`

## Purpose

This package is the single publication boundary between a producer's temporary files and a project-visible completed result. It does not perform reconstruction, own Room schema, or interpret preview/model formats. A result becomes readable only after all required artifacts are copied, synced, hashed, sealed into one manifest, atomically promoted on the same filesystem, revalidated, and accepted by one metadata transaction.

The package also supports original-import batches. Import publication uses the same immutable set protocol but is never exposed as a reconstruction result.

## Public API

- `PublicationIdentity`: project revision, durable operation ID/attempt, input/settings SHA-256 identities, engine version, and purpose.
- `ArtifactDeclaration`: bounded logical artifact, safe relative path, representation name, required/optional flag, and maximum bytes.
- `ArtifactPublicationSession`: `stage`, `stageBytes`, `stageFile`, `seal`, `publish`, and `cancel`.
- `VerifiedArtifactSet`: pointer, decoded manifest, immutable set directory, and logical artifact lookup.
- `PublicationMetadataPort`: Agent 005/006 transaction adapter.
- `ArtifactPublicationSessionFactory` and `VerifiedArtifactSetRepository`: producer/repository integration surfaces, including verified lookup of a specific committed import/result set.
- `recoverAll`: idempotent startup reconciliation.

All filesystem work is blocking and must be invoked from an I/O dispatcher or background worker.

## Storage and state machine

The caller supplies one trusted app-private root. Staging, final sets, journals, and quarantined corrupt journals remain below that root:

```text
staging/<project>/<operation>-a<attempt>/...
sets/<project>/<set-id>/...
journals/<project>/<operation>-a<attempt>.rfpj
quarantine/...
```

The durable journal states are:

```text
OPEN -> SEALED -> PROMOTING -> FILES_PROMOTED
     -> METADATA_COMMITTED -> COMPLETED
```

`ABORTED` and `STALE` are terminal. A state transition is written with a checksum-protected bounded binary envelope. A manifest's `setId` is SHA-256 over its canonical payload. Every present artifact records exact bytes and SHA-256. Required artifacts cannot be absent. Unknown, extra, missing, symlinked, truncated, over-limit, or hash-mismatched members fail validation.

The journal is persisted before producer-visible staging is created. Promotion is one required `ATOMIC_MOVE` from staging to the immutable final directory. Recovery recognizes all six injected boundaries, including metadata committed before its journal update. Repeated recovery is idempotent.

## Metadata transaction requirements

`PublicationMetadataPort.commit` must execute one local database transaction and recheck:

1. project exists and is not deleted;
2. project revision equals `PublicationIdentity.projectRevision`;
3. active operation ID and attempt match and remain `RUNNING`;
4. current result set ID equals `expectedCurrentResultSetId`;
5. publication CAS epoch equals `expectedMetadataVersion`.

`metadataVersion` is a **publication CAS epoch**, not an arbitrary UI/message/progress counter. Increment it when a field relevant to the checks above changes. Do not invalidate publication merely because display progress changed.

For `RESULT_SET`, the transaction must install the verified pointer as current and move the old current pointer to previous. It may not clear previous at job start. For `ORIGINAL_IMPORT`, it must record the committed import pointer, apply photo rows/input mutation, increment the project revision, clear stale current, and retain the old current as previous. `committedPointer(projectId, setId)` must find both result and import publications so reconciliation can distinguish a committed transaction from an interrupted return path.

The coordinator validates these postconditions. A metadata adapter that commits a set but violates current/previous preservation is recorded as failed-contract evidence; the referenced immutable set is not deleted.

## Durability statement

Artifact contents, manifests, and journal files call `FileDescriptor.sync()` before atomic rename. Final set publication requires an atomic same-filesystem directory move. Directory metadata sync is attempted with `FileChannel.force(true)` and recorded in `PublicationDurability` because Android/filesystem support can reject directory handles. Therefore:

- no partially copied artifact is made current;
- a returned verified result has passed full hash/size/member validation;
- sudden-power-loss durability is only as strong as the recorded directory-sync flags and the metadata database's own transaction/WAL guarantees;
- this implementation does **not** claim physical-device power-loss qualification.

## Recovery and retention

Call `recoverAll()` at application/service startup before reopening results or starting a replacement attempt. Incomplete open staging is discarded. Sealed/promoted sets resume only while revision, operation, attempt, current pointer, and publication epoch still match. A stale/cancelled/failed rerun never clears current or previous. Unreferenced staging/final sets are removed with bounded non-symlink traversal. Corrupt journals are quarantined rather than interpreted.

Readers use only `current`/`previous` verified results. They rehash the manifest and every member; corruption is returned as `PublicationReadResult.Invalid`, never as a usable preview.

## Producer mapping

Agent 002 supplies declarations for the actual output set and stages each output through the session. A practical first mapping is:

- required: revision-bound preview/diagnostics JSON;
- required: representation-correct primary model/point export selected by the pipeline contract;
- optional: dense points, mesh, photographic GLB, texture image, auxiliary report when unavailable for a truthful reason.

Absence is explicit in the manifest; do not create placeholder files. The producer must stop using sequential final-path renames and must call `publish()` only after all declared work is complete.

## Validation delivered by this branch

The JVM suite covers all six crash boundaries, stale revision, cancellation, tamper/extra-member rejection, post-commit corruption detection, original-import byte preservation, ambiguous return after a durable transaction, corrupt-journal quarantine, traversal/duplicate paths, and symlink components. The Android instrumentation case exercises immutable directory promotion and coordinator recreation on the app-private filesystem. A true external process-kill/relaunch test remains an integration gate with persistent Room metadata and Agent 088's shared process controller.
