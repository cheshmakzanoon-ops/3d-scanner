# Agent 010 — C9 diagnostics contract

Contract version: `2`

This contract defines machine-readable scan evidence, stage progress and failures. It is an offline local contract. It does not authorize analytics, uploads, private-path logging or embedded photographs.

## Stable types

Source package: `app/src/main/java/com/realityforge/scanner/engine/diagnostics/`

- `DiagnosticScope(jobId, attempt, sourceRevision)` identifies one exact job attempt.
- `ScanStage`, `StageOutcome`, `ScanFailureCode`, `RecoveryAction` and `ProgressUnit` expose stable wire names.
- `StageProgress` has a measured counter and optional measured total. A fraction is valid only for that one stage.
- `StageProgressLedger` rejects stale job identities, decreasing counters, changing units and changing known totals. A retry or checkpoint recomputation must activate a new attempt before resetting a counter.
- `ScanFailure` carries typed codes and an allowlisted `DiagnosticContext`. Context is limited to bounded scalar values and cannot contain file paths, URIs, filenames, arbitrary payloads or photographs.
- `ScanEvidence` keeps visibility, topology, units, calibration assumptions, evidence conditions and stage failures separate. Missing measurements remain `null` or `UNKNOWN`.

No API in C9 computes or accepts a global reconstruction percentage.

## Versioned local report

`ScanQualityReport.build` emits `schema: 2` and `reportType: realityforge.scan_diagnostics`. Existing M19 metric fields remain present for the current UI and historical exports.

New fields:

- `identity`: exact artifact, revision, job/attempt, engine version, settings identity and whether the job ID is explicit, artifact-derived or unbound.
- `evidence.visibility`: evaluated/supported face counts and a fraction only when both counts exist.
- `evidence.topology`: measured boundary/nonmanifold/component/intersection values, otherwise `null`; no watertight claim without corresponding measured zeros.
- `evidence.units`: `UNKNOWN`, `ARBITRARY`, `METRIC_REFERENCE` or `SENSOR_METRIC`; physical units/reference values are forbidden for unknown or arbitrary scale.
- `evidence.calibration`: explicit assumption/profile state and optional measured RMS.
- `evidence.conditions`: independent typed conditions such as sparse fallback, unavailable texture, unknown scale and unobserved surfaces.
- `stageFailures`: typed per-stage failures without raw exception text or private paths.
- `events`: bounded terminal/progress evidence tied to the report identity.
- `outcomes`: stable user-relevant condition codes, stage, outcome, recovery action and localization key.

`validateAndRedact`, `importValidated` and `exportValidated` enforce the 256 KiB report bound, schema, counts/fractions, identity expectations, known enum values, bounded arrays and progress identity. They rebuild output from an allowlist. Unknown private fields and unapproved display copy are not retained. Schema 1 M19 reports migrate to schema 2 as unbound reports; an unbound legacy report cannot satisfy an expected artifact/job/revision check.

## Compatibility and integration

- Existing `status`, count/fraction fields and `recommendations[].action` remain for the M19 screen.
- New consumers should use `messageKey` and `actionCode`; Agents 074/078 own presentation and localization.
- Agent 001/002 should adapt pipeline callbacks to `StageProgress` and exceptions/results to `ScanFailure`; do not parse legacy display strings.
- Agent 009 should supply explicit artifact/job identities. Until then, current M19 output derives an honest `artifact:<artifactId>` job scope and labels the source `DERIVED_FROM_ARTIFACT`.
- Agents 049/055/057 should supply measured visibility/topology/texture evidence. Omitted measurements remain unknown and are never converted to zero.
- Agents 026/067 may expose user-directed local report export only through `exportValidated`; this contract adds no network path.
