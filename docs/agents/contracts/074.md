`ProcessingScreen(JobUiState,onAction,modifier)` presents queued/running/paused/interrupted/failed/cancelled/completed/stale/blocked states separately. Stage progress uses only valid measured completed/total values; unknown totals remain indeterminate and never become global pipeline percentages or an ETA. Technical evidence is expandable. No cached-stage count is inferred.

`JobIdentity(projectId,revision,jobId,attempt,stateVersion)` fences callbacks. `JobActionGate` rejects duplicate concurrent actions. `DurableJobUiAdapter` consumes actual007 `65ec95d6c529c680d649e4bc8a930b67efa127cb` (`JobContracts.kt`,`JobStore.kt`), observes actual Flow snapshots, retains all8 durable states, and copies measured units/settings identity. Cancelled work is terminal and cannot silently retry; stale input cannot resume.

`ProcessingScreen` now requires `onAction: suspend (JobAction) -> Boolean`.
The screen admits an action synchronously through `JobActionGate` before it
launches the dispatcher, and disables every job-action button while pending.
The callback must await actual command admission and return its result; returning
true merely after launching another coroutine violates this contract. Accepted
pause/resume/retry/cancel commands remain pending until the complete persisted
identity changes. A rejected, exceptional or cancelled dispatch releases that
same action; completed previous-result/notification navigation also releases it.
Old callbacks cannot acknowledge a different project/revision/job/attempt/version.
Admission checks the latest composed state even when an older click callback is
delivered. An uncertain dispatch reports an unconfirmed action without claiming
that the reconstruction failed or its state remained unchanged.
The coroutine belongs to the screen composition, so leaving cancels pending UI
dispatch rather than retaining an orphan scope. Receiving owner 071 must adapt
the real executor call and retain its current identity checks.

marker and bounded semantic/callback polling. It does not wait for global UI
idleness: the real running screen deliberately has an animating indeterminate
progress indicator. It asserts disabled pending controls, no duplicate callback,
accepted-action latching and renewed admission only after a new persisted version.
