# Localized presentation contract

Feature resources live in `values/agent_NNN.xml`, names start `aNNN_`, counts use plurals, substitutions use numbered typed placeholders when multiple values occur, and all visible sentences belong in resources. Shared resources use `rf_`; no unreviewed translation is advertised. `UserMessage(code,evidence)` separates an actionable summary from optional technical data. `UserMessageResolver` resolves stable failure categories and photograph plurals. `LocalizedFormats` formats finite numbers, fractions and timestamps with an explicit locale; callers retain unit/scale provenance and layout direction. Avoid concatenated translatable fragments and hard-coded decimal punctuation.

Pseudo-locales `en-XA` and `ar-XB` are test locales, not language support. Device validation must include 200% fonts, RTL, path/measurement isolation, Back/dialog focus, dates and plural zero/one/many. Owner 004 enables `isPseudoLocalesEnabled=true` in debug. Screen owners own migration of their text; backend/notification owner 010 maps structured codes to this contract rather than shipping raw exception strings as the primary message.

Published001 C1 codes are now explicitly mapped by `UserMessageResolver.resolveCode`, without parsing English fallback text. Known operation outcomes, pending/stale requests and project states resolve to resources; unknown codes produce a neutral status message. Partial import does not claim every photograph was accepted, and failed/interrupted deletion never claims originals are unchanged.071 displays localized summaries while keeping old raw project messages in a technical-details disclosure. `projectSummary(state,hasCurrentResult)` uses stable005 machine codes rather than exposing those codes as UI copy.
