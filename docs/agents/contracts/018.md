# Agent 018 contract: photo curation and reconstruction selection

Contract version: `photo-curation-v1`

Owner: Agent 018 (`agents/018-photo-curation`)

## API and ownership

Production API lives in `app/src/main/java/com/realityforge/scanner/data/curation/`.

- `PhotoCurationService.state(projectId)` returns ordered typed curation state.
- `PhotoCurationService.selectedPhotos(projectId)` returns immutable reconstruction inputs.
- `PhotoCurationService.execute(command)` applies one expected-revision command.
- `PhotoCurationStore` is the transactional persistence port for Agents 005/006.
- `SelectedPhotoSet.admitForReconstruction(requiredCount)` returns a fixed lease or typed block.
- `ReconstructionSelectionGuard.verifyPublication` rejects stale publication.

This package never reads, renames, writes, or deletes photograph files. Original-byte lifecycle belongs to repository and deletion owners.

## State and identity

A curated photo has a stable ID, immutable lowercase SHA-256, contiguous zero-based position, and one state: `INCLUDED`, `EXCLUDED`, or `REMOVAL_PENDING`. Pending rows retain request ID, timestamp, removal reason, previous state, and previous exclusion reason. Active pending request IDs are unique within a project.

`SelectedPhotoSet` contains only included photos in their relative order, with compact selected positions. It rejects duplicate IDs, impossible count accounting, and status/count mismatches. Its length-delimited SHA-256 fingerprint covers contract marker, project ID, selected IDs, original hashes, and order. The complete curation-state fingerprint additionally covers pending restore history, so a store cannot silently change an undo/restore target.

## Revisions and changes

`curationVersion` advances for every applied metadata mutation. `projectRevision` advances when selected inputs change, a removal lifecycle starts/ends, or a retained original is verified deleted. No-op commands commit nothing.

Change classes are `RECONSTRUCTION_INPUTS`, `REMOVAL_LIFECYCLE`, `RETAINED_ORIGINALS`, and `METADATA_ONLY`. Reordering only excluded/pending rows is metadata-only when relative selected order is unchanged; it must not stale a current reconstruction lease.

Every command carries the latest complete revision. A stale pair returns `RevisionConflict` with no partial application. The store must atomically compare both revisions, persist the exact next snapshot, update revisions, apply invalidation when requested, preserve the previous completed result, and return the exact committed snapshot. Any returned-state mismatch is `StoreProtocolViolation`.

## Removal and undo

Exclusion is not deletion. `RequestRemoval` emits `PhotoRemovalDirective.Stage`; restore or undo emits `Cancel`. `CompleteRemoval` accepts only the exact staged request ID and original SHA-256 supplied after durable deletion verification, compacts metadata, and has no undo token. Duplicate active generated removal IDs are rejected before commit.

Undo requires matching project identity, exact post-command revision, and exact post-command complete-state fingerprint. Undo creates a new monotonic revision; it never rewinds counters.

## Reconstruction admission and publication

Admission requires `2..4096` selected inputs. Zero is `EMPTY`; any non-empty selection below the requested minimum is `INSUFFICIENT_PHOTOS`. A ready lease contains project ID, project revision, selection fingerprint, and ordered photo IDs.

Immediately before publication, reload the current selected set and verify the lease. Any project, project-revision, fingerprint, or ordered-ID mismatch is `Stale`; partial output must not become current. Reason-only changes and excluded/pending-only reorder do not stale. Include/exclude, selected-order changes, removal lifecycle changes, and verified retained-original deletion do.

## Validation

Agent 018 owns ten JVM unit suites under `app/src/test/.../agents/a018/` and one device contract under `app/src/androidTest/.../agents/a018/`. Coverage includes no-op/revision rules, exact removal lifecycle, unique request IDs, selected-state accounting, custom minimums, undo identity, stale commands/publication, cancellation, store-protocol tampering, deterministic 600-command replay, and retained-original SHA preservation. Connected-device and integrated Agent 073/080 UI gates remain separate required evidence.
