# C13 bounded validated model loading

`PhotographicGlb.read(File)` / `decode(ByteArray)` and the existing
PhotographicAsset geometry/UV/index/image fields remain compatible with the GLES
renderer. Callback overloads accept a cooperative cancellation predicate; each
file-read block, geometry loop and PNG inflate block checks cancellation.
The data class copy method now inherits its internal constructor visibility.

`viewer.loading.GlbStructure.validate(file, expectedPrimitiveMode: Int? = null)`
returns GlbSummary: primitiveMode, vertexCount, indexCount, representation, units,
hasPhotographicTexture and estimatedResidentBytes. Byte-array and callback
variants support an already bounded upload. This structural inspector supports
single embedded POINTS/TRIANGLES assets, including 061 canonical outputs and
legacy point/mesh outputs. It rejects extra scenes/nodes/primitives, transforms,
external URIs, animations/skins, unknown required/used extensions, unused
accessors, aliased ranges, invalid strides, nonfinite attributes, lying bounds
and invalid triangle indices. KHR_materials_unlit is supported. This is a bounded
subset, not a general glTF importer: explicitly unsupported models fail closed.

`PhotographicModelLoader.load(file)` is suspendable and bound to the caller job.
It returns LoadedPhotographicModel with legacy asset, GlbSummary and read-only
original GLB ByteBuffer. Closing twice is safe; access after close fails. The
renderer must finish GPU ownership before closing, and must not mutate the
legacy asset arrays shared with GLES. They remain arrays for source compatibility;
this contract does not claim deep immutability against a malicious in-process
caller. No global cache keeps loaded assets alive. New production paths should
use the one-owner lease and read-only original bytes rather than retaining
independent GLB/PNG copies in navigation state.

Limits: 32 MiB GLB file, 256 KiB JSON, nesting 32, 16 views, 8 accessors,
2 million structural vertices, 12 million structural indices and 192 MiB
conservative combined file/CPU/decode/GPU estimate. Photographic preview retains
its tighter 240,000 vertices/indices, 4.5 million image pixels and 20 MiB encoded
PNG limits. PNG CRC, chunk order, noninterlace RGB/RGBA8, exact zlib scanline size,
filter bytes and end-of-stream are checked with a 16 KiB inflate buffer before
bitmap allocation; decompression bombs cannot hide under small IHDR dimensions.
These are admission bounds, not measured physical RAM/GPU-performance budgets.

Strict JSON validation rejects duplicate property names and Android JSONTokener's
nonstandard comments/unquoted keys/single quotes/semicolon/trailing-comma syntax;
malformed UTF-8 is rejected instead of silently replaced.

Host corpus: set RF_ANDROID_JSON_JAR to Maven
`com.vaadin.external.google:android-json:0.0.20131108.vaadin1` and run
`python -m pytest tests/test_agent_068_parser_host.py -q -s`. The test uses cached
pinned Kotlin 2.1.21 and coroutines 1.10.2, compiles the actual production parser
and runs a Java driver with real Android JSON behavior, not mockable android.jar.
Without those host prerequisites it explicitly skips; Android corpus is separate:
`...gradle... :app:connectedDebugAndroidTest
-Pandroid.testInstrumentationRunnerArguments.class=com.realityforge.scanner.agents.a068.GlbParserCorpusTest`.
No host result substitutes for Android renderer/device lifecycle evidence.

and photographic UV/image compatibility. All images/geometry are synthetic.
