# Agent 026 — SAF export transfer contract

Contract version: `saf-export-v1`

## Purpose

This contract separates format production from user-directed Android document transfer. A
format/archive owner supplies a byte-exact `VerifiedExportSource`; the activity/export
orchestrator binds a picker callback to an immutable `DestinationSelectionRequest`; and
`DestinationTransferService` performs the copy without consulting mutable project selection.
No interface in this package uploads data or encodes a model/archive format.

## Immutable identities

`ExportSourceIdentity` contains:

- `projectId`: stable project identifier.
- `revision`: exact source revision, as a non-negative integer.
- `artifactKey`: canonical committed artifact/stage key from Agents 009/023.
- `representation`: explicit representation/format identifier, such as `model/glb` or
  `capture-archive/zip`.

`VerifiedExportSource` adds expected byte length, lowercase SHA-256, display name and MIME
kind. The source resolver must return the same identity and revalidate length/hash before,
during and after transfer. A source change is a typed failure, never a successful export.

## Picker binding

`DestinationSelectionRequest` is created before launching the Android picker. The activity
result is represented by `DestinationSelectionCallback` and accepted only when request ID,
selection mode and ownership agree. `BoundDestinationRequest` copies the original immutable
source identity into the callback result. The callback must not read the currently selected
project, current preview or latest revision.

Ownership has two values:

- `NEWLY_CREATED`: the app owns only this newly created output and may request deletion after
  an incomplete transfer when the provider advertises safe deletion.
- `PRE_EXISTING`: the user supplied an existing document. Failure cleanup must retain it,
  even when it may contain partial bytes.

Provider capabilities are evidence, not promises manufactured by the app. Unsupported
read-back, size query, temporary-document or atomic-commit behavior remains explicit.

## Transfer service

`DestinationTransferService(VerifiedExportSourceAccess, DestinationDocumentStore)`:

1. rejects source/request identity mismatch before opening a destination;
2. verifies the staged source identity, length and SHA-256;
3. streams through a bounded 4 KiB–1 MiB buffer with coroutine and explicit cancellation;
4. verifies the bytes copied and rechecks the source revision/artifact;
5. uses destination read-back SHA-256 when available, otherwise size-only or provider-close
   evidence without claiming exact verification;
6. commits a provider temporary document only through `PreparedDestination.commit()`;
7. performs one final source verification before publishing a receipt; and
8. aborts on failure, deleting only an owned newly-created incomplete output when supported.

A provider adapter may use a temporary document only when its provider-specific implementation
can prove creation/commit/cleanup ownership. The default `AndroidSafDestinationStore` performs
a direct non-atomic write and labels it `DIRECT_NON_ATOMIC`; it never invents atomicity.

## Outcomes

- `VerifiedSuccess`: destination bytes were read back and matched expected length/SHA-256.
- `CompletedUnverified`: the provider accepted the stream but exact destination bytes could
  not be proven. The warning includes unavailable atomicity and an explicit review action.
- `Cancelled`: cancellation was observed and cleanup disposition is recorded.
- `Failure`: typed source binding/change, permission, unavailable provider, storage exhaustion,
  content mismatch, commit or generic I/O failure, with bytes copied and recovery action.

Cleanup is always one of the typed `CleanupDisposition` values. No outcome tells the caller to
delete an unrelated or pre-existing document.

## Integration boundaries

- Agent 001 owns activity-result registration and must bind results to the exact request ID.
- Agents 006/023 provide canonical, revision-bound source resolution and publication leases.
- Agent 067 owns export eligibility, format selection and user-facing orchestration.
- Agent 025 supplies archive streams through the same `VerifiedExportSource` contract.
- Agent 021 supplies storage admission for any future local/provider temporary staging.
- Agent 088 owns the test-only `DocumentsProvider` and process controller used for the real SAF
  fault matrix. Agent 026 supplies transfer scenarios and assertions, not a competing provider.
