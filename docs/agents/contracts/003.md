# C3: bounded JNI and exported native ownership

The application uses `NativeCore` declarations and the matching `jni.cpp` exports.
The implementation retains the existing numeric layouts and coordinate conventions;
it does not reinterpret sparse points as a mesh or change reconstruction acceptance
thresholds to make boundary tests pass.

## Failure and ownership rules

| Boundary | Contract |
| --- | --- |
| JNI arrays and scalars | Check required arrays, exact row layout, bounded counts and representable products before copying/allocating; reject non-finite supplied numeric values. |
| JNI strings | `rf::jni::UtfChars` bounds the modified-UTF input, owns the acquired buffer and releases it through RAII, including exceptional exits. |
| JNI exceptions | Every exported entry contains C++ failures. `std::bad_alloc` becomes the VM allocation exception; invalid input and other failures remain typed. `rf::jni::raise` preserves any exception already pending in the VM. |
| Native operations | Begin returns a nonrecycled operation identity. Active calls retain shared cancellation state; finish removes the registry reference without freeing state still held by an active call. Independent tokens cannot cancel each other. |
| Exported `rf_*` C ABI | Existing JSON-producing wrappers and `rf_free` are `noexcept`. The bounded stack error encoder cannot throw while formatting an allocation failure. |
| C return allocation | A non-null JSON result is caller-owned and must be passed once to `rf_free`. If even bounded error-result allocation fails, return null. Null is a recoverable allocation failure; `rf_free(nullptr)` is valid. The Python ctypes adapter checks null before reading and releases non-null buffers in `finally`. |
| Optional stage results | `NativeResultJson.decode` propagates `RESOURCE_EXHAUSTED` and `CANCELLED`. A memory or cancellation error is never downgraded to successful sparse/mesh/texture fallback. |

`exportPoints` retains its legacy sparse behavior. The additive `exportPointCloud`
method carries an explicit sparse/dense choice and uses independent output files.
Both GLB POINTS metadata and PLY headers must describe their actual representation.
Triangle exporters remain distinct native APIs.

The accepted-surface texture-only API added during the audit follows the same
boundary guards. Its verified `surface-v1.rfmesh` checkpoint and native behavior
proof belong to the 002/009 integration described in `../audit/B-to-001-review.md`.
A checkpoint rejection may request recomputation; cancellation/resource exhaustion
must propagate. A cache hit does not count as a newly written native checkpoint.

## Executed and outstanding evidence

The actual native implementation introduced in `50a2d84` passed 12 CTest targets,
including `native_boundary_contract`. That compiled target injects real global
allocation failures across all seven existing C JSON exports and validates point
representation labels. The exact host log is retained in
`../audit/003-native-ctest.log`; its SHA-256 is recorded in `../status/003.md`.

Host JNI syntax checks were also executed during integration. Neither syntax checks
nor host allocation-failure tests establish Java resource behavior on a device.
`JniBoundaryDeviceTest` supplies real Android tests for malformed arrays/scalars,
stale handles, capacity recovery and absent output after invalid export. Actual
ARM64/x86_64 loading, repeated active-call begin/cancel/finish races, sanitizer runs
and minified release loading remain required gates in the final candidate audit.
