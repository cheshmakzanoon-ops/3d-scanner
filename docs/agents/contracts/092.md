# Agent092 runner contract

`bash tools/run-device-tests.sh --serial SERIAL --app-apk APP.apk --test-apk TEST.apk --output DIRECTORY [--expect-api N] [--expect-abi arm64-v8a|x86_64] [--expect-page-size 4096|16384]` uses prebuilt APKs and returns 0 only after nonzero passing instrumentation and a fresh decoded full-session PNG. With no arguments it builds first and requires exactly one authorized device. Reports are compatibility.json, instrumentation.txt, photographic-viewer.png. Missing devices/screenshots/zero tests/candidate/environment mismatches return nonzero. No uninstall or data clearing. CI093 may invoke the script directly with exact candidates and serial. Installed base-package hashes are checked after installation, preventing a wrong-package APK from qualifying an older installed app. Split packages require separate full identity receipts. Artifact hashes and runtime16kb/physicalCapture gate distinctions are in JSON. Device tests require a disposable installation because existing instrumentation creates/deletes test projects.

`runner.instrumentation_counts(output)` validates raw `-r` status events keyed by(class,test,current). Code0=passed,-3=ignored,-4=assumption skipped,-1/-2=failed. It requires complete unique start/terminal pairs, declared numtests matching terminal_count, at least one actualpass and no failures. JUnit OK(N) must equal terminal_count minus ignored; assumptions remain in N. Receipt `counts={tests,passed,skipped,failed}` preserves those distinctions; legacy `tests` equals counts.tests. Source: actual AndroidJUnitRunner1.6.2 InstrumentationResultPrinter bytecode, checked with javap. CI093 validates these fields independently against the raw transcript.
