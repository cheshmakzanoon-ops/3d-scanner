# Project-bound navigation and launcher contract

`AppRoute` encodes library/review/capture/processing/studio/export/settings/help routes with explicit project identity. Back returns project features to review, then library. Settings/help retain their initiating project. Route and picker envelopes are saved independently of ViewModel selection. A `PendingRequest` fixes request ID, kind, project ID, revision and export artifact/extension. Callback consumption clears it exactly once and rejects changed project/revision/artifact/busy state before calling any legacy controller. Cancelled/stale camera files are deleted rather than imported into another project. The fixed request survives activity recreation; exact durable owner admission remains a001 integration request.

ScannerApp delegates real feature bodies to072/073/074/075/079, AppTheme to076, current-file export eligibility to067, numerical/viewer work to existing070-owned viewers, and all mutation/reconstruction work to baseline001 ViewModel. Absent curation/library commands/durable-job capabilities are never offered as working actions. No branch imports foreign Git histories. Dependency contributions are supplied through ordinary integration; temporary source-set testing does not claim the single branch independently contains them.

Tags are exposed as resource IDs from the root semantics node. Route tags are `a071-route-<destination>`, common help/settings buttons `a071-open-help`/`a071-open-settings`, photographic open/export controls `a071-open-photographic`/`a071-open-export`; format buttons `a071-export-<suffix>`. Feature owners publish their controls. User-facing shell text lives in agent_071.xml, never milestone text.

First launch reads079 preferences off the main thread, shows the local075 guide once, and persists completion/skip version. User preference theme is applied to076 AppTheme; fallback focal is supplied only as the initial value for a newly opened review, without mutating active jobs. Unknown/deleted restored project IDs return safely to library after a repository lookup. Headings are semantic landmarks; route changes and picker completion restore keyboard focus to the route title rather than a stale destructive action.

067's checksummed PendingExportStore is saved before launching the provider and revalidated by original metadata hash before the legacy export call. Invalid persisted bytes require explicit user-directed quarantine; valid pending requests are never silently overwritten. A visible cancel-pending action permits recovery if a process dies after saving but before picker launch, and causes any later callback to fail closed. Provider byte transport still belongs to026/001 integration; this shell does not duplicate that subsystem.

Processing action acknowledgement:071 supplies074 a `suspend (JobAction) -> Boolean` callback. The complete fixed identity and current selected project/revision are checked before dispatch. Durable commands directly await the actual008/007 executor Boolean; a missing executor rejects rather than falling through to a legacy command. Legacy pause additionally checks active reconstruction job/source identity; retry requires current failed/interrupted inputs and returns the real synchronous C1 reservation busy flag; viewer navigation requires a matching current result. Unsupported/stale commands return false.074 owns production admission/pending/rejection acknowledgement so repeated clicks cannot bypass the action gate through a nested launch.

Picker callback ownership follow-up: import, calibration, and the shared model/archive export launcher each have a versioned, bounded `rememberSaveable` slot containing the complete immutable initiating PendingRequest. The slot is installed on the main thread immediately before synchronous launcher invocation; synchronous launch failure releases only that slot. Android delivers one result per accepted launch. Cancellation releases the C1 intent but retains the saved cancelled slot until that result drains, blocking reuse of the same launcher. Other kinds may proceed only if C1 admits them. An old callback consumes only its slot and clears the logical UI pending value only on full snapshot equality; it never clears or cancels another request. Camera close/photo callbacks capture that camera composition's full request and reject old photos without changing a newer camera route.

Activity recreation/process restoration retains the same slot snapshot alongside ActivityResultRegistry state. A cancelled tombstone remains blocked until the platform result drains; a missing callback remains explicitly blocked with an explanation rather than silently rebinding to a new request. Invalid/unknown slot schemas fail closed. A pre-launch durable export intent with no launcher slot can still be restored for explicit cancellation, without automatically launching or transferring. An existing slot permits restoration only for its exact uncancelled origin. The same bounded saved slot record retains the full last-consumed model-export origin after its platform callback drains; restoration rejects that request ID even if Activity recreation happens before asynchronous private-store cleanup. Cleanup or unrelated picker activity never clears this marker. Only a later actual model-export callback replaces it, after the single-record durable store has admitted that newer intent. On startup, an exactly matching saved consumed or cancelled model-export origin terminally cancels only that restored legacy C1 request ID and clears only its matching durable record. This releases an admission restored after death before callback-finally cleanup, without replaying transport or touching a mismatched/newer intent. The saved marker/tombstone remains; startup reconciliation does not release an outstanding platform launcher slot.

Startup export reads capture both pending and launch mutation epochs plus the initial pending snapshot. A read begun before a callback, cancel, new request or launch change cannot resurrect a consumed intent or reintroduce stale recovery state. Export return compares stored ID/project/revision/artifact/option to the slot's origin, validates current bytes, and passes that exact C1 request ID to transport. Every exit cancels only the original unclaimed C1 intent; C1 atomically removes a claimed request before transport, so this does not abort an active transfer. Mismatched valid store bytes are retained, never cleared as a different request. Explicit cleanup is ID guarded. An unconfirmed result explains that the picker may have created an empty/incomplete destination; no provider-close or partial-destination deletion guarantee is added. Composition cancellation before C1 admission rejects that return and preserves unconfirmed status; a claimed transfer is owned by the ViewModel, not the UI coroutine.

Physical process-kill/platform delivery coverage remains a separate device gate.
