# Shared test faults and external recovery

The test APK alone registers `com.realityforge.scanner.test.faults`. Use `DocumentsContract.buildDocumentUri(authority, mode)`: normal, truncated (64 bytes), slow (10ms/1KB), revoked (open rejected), short-write (8-byte writes then EIO after 32), enospc (proxy FD throws ENOSPC; no disk filling). CancellationSignal is honored. The provider uses the framework-required MANAGE_DOCUMENTS permission. Direct instrumentation access adopts shell MANAGE_DOCUMENTS only for the test and drops it in finally; picker-mediated access uses normal URI grants. Only synthetic relief fixtures are exposed; provider never accepts arbitrary paths or stores user data. 026/080 reuse this provider and manifest; do not register duplicates. App-owned transfers must report external partial writes truthfully.

Install exact debug app/test APKs and run `python tools/device/failure_recovery/controller.py --serial SERIAL --source-sha SOURCE40HEX --stage import --app-apk APP.apk --test-apk TEST.apk --output reports/recovery/import`. Repeat registration, mesh-texture, checkpoint, publication. Candidate paths are hashed and compared against installed base APK hashes. Explicit serial always selects all adb calls. The host polls nonce+stage readiness, checks the actual target PID, kills with target UID, waits for death, invokes a new instrumentation process, checks both PIDs/revision and the real repository's original hashes, reruns actual SparsePipeline, then publishes and reopens the matching result. Sessions use only test-created UUID projects. A failed run retains its project/state for diagnosis; successful runs clean it up.

These are existing observable **boundaries**: registration at sparse triangulation start, mesh-texture before combined JNI, checkpoint after combined depth/mesh/texture completion, publication before database completion. They do not prove in-native-stage kill safety. The checkpoint case snapshots actual cache hashes across death, corrupts exactly one reference in its disposable project, and requires selective valid-cache reuse plus exactly one rewritten map. Existing per-reference cache tests remain; source-owner hook request 088-to-002/050 covers exact checkpoint and mesh/texture interruption. Never relabel the coarse boundaries as those finer scenarios. Installed schema upgrades use the same controller with `--upgrade-app-apk NEW.apk --upgrade-test-apk NEW-TEST.apk`; after verified external death it installs both with `-r -t`, checks installed upgrade hashes, then verifies preserved originals/revision and resumed results using the new process. Both old/new app and test hashes are recorded; attach version codes and migration result as well. Do not uninstall or clear data. Production nondebuggable candidates require authorized external process hooks; run-as is intentionally unavailable there.

All scenarios remain NOT_RUN until device execution. API/ABI/emulator identity and actual command stdout accompany each receipt. External force-kill is distinct from ViewModel recreation and does not establish actual power-loss durability.

## Configurable bounded provider API v1

The sole test-APK provider now additionally exposes request-isolated documents.
Use `ContentResolver.call(Uri.parse("content://com.realityforge.scanner.test.faults"),
"qa.configure", null, Bundle().apply { putString("config", CONFIG_JSON) })` while
adopting `android.permission.MANAGE_DOCUMENTS` for the test only, dropping it in
`finally`. Administrative calls enforce this permission explicitly. This API never
accepts filesystem paths and cannot reset all application/test data. Example:

```json
{"schema":1,"synthetic":true,"requestId":"export_case_001","mode":"silent-truncate","limitBytes":17,"verification":"readback","deleteFails":false,"preExisting":false,"created":true}
```

Configuration returns `documentId=request/export_case_001` and
`parentDocumentId=request-root/export_case_001`; construct URIs using
`DocumentsContract.buildDocumentUri`. Request IDs are1–64 ASCII letters/digits,
underscore or hyphen; existing IDs require explicit `qa.reset` before reuse.
At most16 requests,1MiB retained payload per request,256 retained events/request,
25ms maximum callback delay and16MiB total accepted-write budget/request are
permitted. No disk exhaustion loop or arbitrary external path is used. Consumers
must choose a synthetic export fixture within the advertised1MiB payload bound.
Numeric/boolean fields have strict types, unknown fields fail and synthetic=true
is mandatory.

Modes: `normal`, `slow`, `silent-truncate`, `enospc`, `edquot`, `revoked`,
`revoke-readback`, `missing`. `limitBytes` controls silent truncation or the exact
retained prefix before ENOSPC/EDQUOT; normal/slow payloads retain exact bytes up to
the1MiB bound. Silent truncation reports accepted writes and closes successfully
while retaining only the prefix, allowing026 to prove that close alone is not
verified success. `revoked` throws SecurityException before open (distinct from
FileNotFoundException for `missing`); `revoke-readback` allows the write then
throws SecurityException when verification reopens it. Legacy `revoked` was also
corrected to SecurityException. `qa.revoke` with request ID as `arg` revokes a live
request: future opens throw SecurityException and already-open proxy callbacks
fail with EACCES, which Android surfaces as an I/O error. Do not relabel that
already-open-descriptor errno as a Java SecurityException.

`verification=readback` exposes exact retained bytes; `size-only` exposes
OpenableColumns.SIZE but refuses readback; `none` returns null size and refuses
readback. The consumer must declare corresponding conservative capabilities;
the provider does not fabricate verified or atomic completion. `created=false`
allows one genuine `DocumentsContract.createDocument` under its returned parent.
`deleteFails=true` records deletion attempts but preserves the payload;
successful deletion retains its audit record. `preExisting` is recorded and
exposed;026's ownership policy must prove zero delete calls for pre-existing
outputs. The provider deliberately logs any attempted deletion instead of hiding
an erroneous consumer call. Temporary commit/abort is unsupported; the correct
Android store classification remains DIRECT_NON_ATOMIC.

`qa.snapshot` with request ID as `arg` returns Bundle string `json`: immutable
config, created/deleted/revoked state, write/read-open counts, accepted/stored-byte
counts, delete-call count, retained payload size/SHA256, configured/current
provider PIDs and sequenced elapsed/wall-time events with dropped-event count.
Payload and atomic JSON metadata are in the test APK's private files directory;
each write is synced and every callback rereads durable metadata. The state is
queryable after client death/provider restart; actual process-restart durability
execution remains NOT_RUN. `qa.reset` removes only the named request and refuses
while its descriptors are active. Close descriptors before reset and allow
asynchronous close callbacks to finish. Logs may be bounded, never silently
claimed complete when droppedEvents>0.

The two new methods in RecoveryStageContractTest compile real resolver/provider
contracts for exact bytes, silent truncation, quota prefixes, capability evidence,
creation/deletion, permission classification, path/size bounds and cleanup. These
are provider contracts;026's real DestinationTransferService typed outcomes and080
UI recovery remain separately NOT_RUN until their actual sources are integrated
and run. No duplicate provider/manifest was introduced.

Existing baseline controller now requires `--source-sha SOURCE40HEX`, records
operator-supplied immutable source mapping separately from independently checked
installed app/test hashes, API/ABI/device-identity hash and start/end timestamps.
Verification and cleanup each require complete raw status1→0 events for exactly
RecoveryStageContractTest#externalProcessBoundary, OK(1 test) and final
INSTRUMENTATION_CODE:-1. Ignored/assumption/wrong-class/duplicate/truncated runs
fail. Source SHA alone does not prove APK provenance: retain the candidate build
manifest mapping those hashes to the source. No new-provider product acceptance
is implied by this baseline controller pass.
