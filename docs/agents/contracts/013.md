# Agent 013 contract — capture and lens metadata identity

Schema owner: Agent 013
Package: `com.realityforge.scanner.capture.metadata`
Wire schema: `RF_CAPTURE_METADATA_V1`
Optical identity schema: `RF_CAPTURE_OPTICAL_IDENTITY_V1`

## Production types

- `CaptureMetadata` is immutable and has schema version 1. It carries capture-source labels,
  image dimensions, encoded orientation, logical and explicitly bound physical camera IDs,
  reported camera/lens strings, zoom, active-array-relative crop, physical sensor size,
  sensor orientation, focal length, 35 mm equivalent and original-metadata retention state.
- Every optional field is a `FieldEvidence<T>` with `MISSING`, `OBSERVED`, `DERIVED` or
  `CONFLICTING` status. It retains all source observations, checked origins and bounded
  relative uncertainty. Missing data has no default value; conflicting data has no selected
  value.
- `CaptureMetadataIssue` records invalid source values or unavailable synchronized camera
  results. These are evidence, not a success/failure replacement.
- `CaptureMetadataMerger.merge` combines independent camera and EXIF records. It keeps
  disagreements, accepts only narrowly equivalent rounded numeric observations, and never
  promotes a logical camera's list of possible physical devices to the active physical ID.

## Canonical serialization and identity

`CaptureMetadataCodec.encode` produces bounded canonical UTF-8. The reader rejects unknown
versions, duplicate/unknown keys, noncanonical numbers/base64, malformed evidence and files
larger than 64 KiB. `decode(encode(x))` preserves the complete record.

`CaptureMetadataCodec.opticalIdentitySha256` hashes the canonical reconstruction-relevant
projection. The projection includes values, status, provenance, uncertainty, conflicts and
source issues. It excludes `originalMetadataRetained`, because export/privacy treatment must
not invalidate reconstruction geometry. A changed lens, zoom, crop, orientation, focal value
or evidence quality changes the identity.

## Compatibility contract

`LensCompatibilityAssessor.assess(reference, candidate)` returns a deterministic
`LensCompatibilityResult`:

- `COMPATIBLE`: direct physical-camera identity plus complete, matching direct optical
  evidence. Strict calibration-profile reuse is allowed.
- `COMPATIBLE_WITH_UNCERTAINTY`: no contradiction, but identity/evidence is incomplete or
  derived. Provisional same-optics grouping is allowed; strict calibration reuse is not.
- `INSUFFICIENT_EVIDENCE`: no contradiction can be proven, but there is too little evidence
  to group captures. Independent intrinsics are required.
- `INCOMPATIBLE`: a physical/logical/lens identity, zoom, crop, orientation, aspect, sensor or
  focal mismatch, or conflicting optical evidence. Shared calibration/intrinsics are rejected.

Reason codes are sorted enum values and are stable machine-readable diagnostics. Missing
metadata never becomes a 1x zoom, full crop, normal orientation or physical-lens match.

## Android adapters

- `ExifCaptureMetadataAdapter.read(file, fallbackImageSize)` is read-only. It extracts
  orientation, focal values, digital zoom and reported make/model/lens fields while preserving
  the original file bytes. EXIF cannot provide a Camera2 physical ID, so that field remains
  explicitly missing.
- `CameraCaptureMetadataAdapter.fromCamera2` consumes synchronized `CaptureResult` values and
  `CameraCharacteristics`. `fromCameraX` uses Camera2 interop plus CameraX runtime zoom as a
  clearly derived fallback. A physical ID is populated only when the capture-session owner
  passes the actual bound/callback ID.

## Consumer rules

- Agent 009 uses only `opticalIdentitySha256` as the metadata component of stage input
  identity; do not hash display JSON or nullable database columns independently.
- Agent 027 requires `mayShareCalibrationProfile == true` before automatic profile reuse.
  Uncertain results must remain visible and use independent/refined intrinsics until validated.
- Agents 011/014/015 preserve the immutable metadata record from ingestion/capture through
  publication. They must not infer the destination project from mutable UI selection.
- Agent 010 may map the reason enums to diagnostics, but display/localized text remains outside
  this package.

Original EXIF preservation and user-selected metadata stripping on derived exports are
separate operations. This contract performs no telemetry, upload, runtime model fetch or
original-file mutation.
