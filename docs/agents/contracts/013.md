# Agent 013 contract — capture and lens metadata identity

Schema owner: Agent 013  
Package: `com.realityforge.scanner.capture.metadata`  
Wire schema: `RF_CAPTURE_METADATA_V1`  
Optical identity schema: `RF_CAPTURE_OPTICAL_IDENTITY_V1`

## Production types

- `CaptureMetadata` is immutable and has schema version 1. It carries capture-source labels,
  an optional opaque app-local capture-device namespace, image dimensions, encoded orientation,
  logical and explicitly bound physical camera IDs, reported camera/lens strings, zoom,
  active-array-relative crop, physical sensor size, sensor orientation, focal length, 35 mm
  equivalent and original-metadata retention state.
- `captureDeviceId` is supplied by the capture/session owner from durable app-local state. It
  must be a random opaque namespace, not a hardware serial, advertising identifier or account
  identifier. The metadata adapter never invents it. Camera2 logical/physical IDs are only
  interpreted inside this namespace.
- Every optional field is a `FieldEvidence<T>` with `MISSING`, `OBSERVED`, `DERIVED` or
  `CONFLICTING` status. It retains all source observations, checked origins and bounded
  relative uncertainty. Missing data has no default value; conflicting data has no selected
  value.
- `CaptureMetadataIssue` records invalid source values or unavailable synchronized camera
  results. These are evidence, not a success/failure replacement.
- `CaptureMetadataMerger.merge` combines independent camera and EXIF records. It keeps
  disagreements, accepts only narrowly equivalent rounded numeric observations, and never
  promotes a logical camera's list of possible physical devices to the active physical ID.

## Canonical serialization and identity

`CaptureMetadataCodec.encode` produces bounded canonical UTF-8. The reader rejects unknown
versions, duplicate/unknown keys, noncanonical numbers/base64, malformed evidence and files
larger than 64 KiB. `decode(encode(x))` preserves the complete record.

`CaptureMetadataCodec.opticalIdentitySha256` hashes the canonical reconstruction-relevant
projection. The projection includes the capture-device namespace, values, status, provenance,
uncertainty, conflicts and source issues. It excludes `originalMetadataRetained`, because
export/privacy treatment must not invalidate reconstruction geometry. A changed device
namespace, lens, zoom, crop, orientation, focal value or evidence quality changes the identity.

## Compatibility contract

`LensCompatibilityAssessor.assess(reference, candidate)` returns a deterministic
`LensCompatibilityResult`:

- `COMPATIBLE`: matching app-local capture-device namespace and physical-camera identity plus
  complete, matching direct optical evidence. Strict calibration-profile reuse is allowed.
- `COMPATIBLE_WITH_UNCERTAINTY`: no contradiction, but device identity or optical evidence is
  incomplete/derived. Equal Camera2 IDs without a capture-device namespace are only weak
  evidence. Provisional grouping is allowed; strict calibration reuse is not.
- `INSUFFICIENT_EVIDENCE`: no contradiction can be proven, but there is too little evidence
  to group captures. Independent intrinsics are required.
- `INCOMPATIBLE`: a capture-device, camera model, physical/logical/lens identity, zoom, crop,
  orientation, aspect, sensor or focal mismatch, or conflicting optical evidence. Shared
  calibration/intrinsics are rejected.

Reason codes are sorted enum values and are stable machine-readable diagnostics. Missing
metadata never becomes a 1x zoom, full crop, normal orientation, same capture device or
physical-lens match.

## Android adapters

- `ExifCaptureMetadataAdapter.read(file, fallbackImageSize)` is read-only. It extracts
  orientation, focal values, digital zoom and reported make/model/lens fields while preserving
  the original file bytes. EXIF cannot provide a Camera2 physical ID or app-local device
  namespace, so both remain explicitly missing.
- `CameraCaptureMetadataAdapter.fromCamera2` consumes synchronized `CaptureResult` values and
  `CameraCharacteristics`. `fromCameraX` uses Camera2 interop plus CameraX runtime zoom as a
  clearly derived fallback. Android build manufacturer/model are diagnostic evidence only.
  A physical ID and capture-device namespace are populated only when the session owner passes
  the actual bound/callback ID and durable app-local namespace.

## Consumer rules

- Agent 005 persists the canonical blob and schema/identity columns described in
  `docs/agents/requests/013-to-005.md`; old rows remain explicit unknowns.
- Agent 009 uses only `opticalIdentitySha256` as the metadata component of stage input identity;
  do not hash display JSON or nullable database columns independently.
- Agent 027 requires `mayShareCalibrationProfile == true` before automatic profile reuse.
  Uncertain results remain visible and use independent/refined intrinsics until validated.
- Agents 011/014/015 preserve the immutable metadata record from ingestion/capture through
  publication. They must not infer the destination project from mutable UI selection. Camera
  owners pass the durable app-local device namespace and the actual active physical camera ID.
- Agent 010 may map reason enums to diagnostics, but display/localized text remains outside
  this package.

Original EXIF preservation and user-selected metadata stripping on derived exports are
separate operations. This contract performs no telemetry, upload, runtime model fetch,
hardware-identifier collection or original-file mutation.
