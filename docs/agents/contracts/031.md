# Pixel geometry contract — Agent 031

`PixelTransform.VERSION=2`: integer image coordinates locate pixel centres. Resize maps
`u'=(u+.5)*targetWidth/sourceWidth-.5` and likewise v. EXIF stored-pixel orientation (all eight
values), upright crop, then resize compose with `first.then(next)`. `map` and `inverse` are
mutual affine inverses. `intrinsics` returns the full row-major 3x3 `A*K`; orientation may
introduce off-diagonal terms and reflections, which cannot be reduced to positive fx/fy.
Camera rays remain x-right/y-down/z-forward. Poses remain row-major world-to-camera and
world scale remains arbitrary. Orientation changes image coordinates only.

`LensProfile.forScan` applies this resize rule to calibrated upright intrinsics. Its aspect/lens
checks remain active; measured profiles are never converted to estimated pinholes. `normalized`
uses Brown–Conrady inversion with positive local Jacobian checks. `validateDomain` tests a 17x17
image-domain grid with maximum reprojection residual 1e-5 pixels, then every ray is checked at use.
A finite grid is not a proof of global injectivity between samples; per-ray validation remains
mandatory. Transform composition round trips target 1e-10 pixels; numerical projection tests
allow 1e-5 pixels when finite differencing is involved.

New geometry identity: `LensProjection.COORDINATE_CONVENTION =
rf-xright-ydown-zforward-w2c-pixel-centres-v2`. Changing the centre convention invalidates matching,
alignment, depth, surface, and photographic projection; feature descriptor pixels themselves are
unchanged. Owner009 must include this version, and owner027 must retain original calibration
provenance while reprojecting derived stages. Old profiles store calibration image coordinates,
so no destructive rewriting of calibration coefficients is needed.
