# Agent 007 contract: durable reconstruction jobs

This contract owns the persistent execution ledger under
`com.realityforge.scanner.data.jobs`. It does not own Android service lifecycle,
pipeline algorithms, project schema registration, artifact manifests or atomic
publication.

## Stable types

- `JobInputSnapshot` binds project ID, fixed source revision, request ID, input,
  calibration, settings and engine SHA-256 identities, plus engine version and
  schema version. Its length-prefixed canonical hash is the durable job identity.
  Repeating the exact request is idempotent; any bound field change creates a new
  job and marks an older active job for that project stale.
- `JobId` is stable for the lifetime of a row. `attempt` starts at zero and is
  incremented only when a queued job is acquired.
- `JobStageCursor` records the last accepted coarse stage. `CREATED` has no
  checkpoint; every later accepted stage must carry an immutable artifact
  identity and SHA-256 checksum. A worker may advance exactly one stage at a
  time. Recovery may retain or roll back an accepted cursor but cannot invent a
  later stage or replace a checkpoint at the same stage.
- `JobSnapshot` is the complete immutable read model. Terminal states are
  `COMPLETED`, `FAILED`, `CANCELLED`, `STALE` and `BLOCKED_EXTERNAL`; `PAUSED`
  remains resumable but requires an explicit resume command.

## Lease and publication fence

`acquireNext` uses a compare-and-set state version and returns a `JobLease` bound
to all of:

1. job ID;
2. monotonically increasing attempt;
3. unguessable token;
4. worker ID;
5. absolute expiry; and
6. current state version.

Every worker mutation validates the complete lease. A renewal, accepted stage or
persisted progress record advances the state version and returns the replacement
lease. The previous value is immediately stale. `relinquish` validates the
worker's lease before moving the job to `PAUSED`; resume followed by acquisition
creates a new attempt. Completion from an expired, paused, cancelled, stale or
superseded worker is rejected with `JobLeaseRejectedException`.

Agent 023 must validate the current lease immediately before atomic publication
and call `complete` with the same returned lease and verified artifact identity.
Its journal remains responsible for removing or reconciling unreferenced staged
files if the fence changes between filesystem work and database commit.

## Recovery

`recoverExpired` considers only `RUNNING` rows whose lease is expired. A supplied
`JobCheckpointValidator` must verify the actual artifact bytes and C8 manifest,
then return either an accepted cursor or a restart decision. Recovery executes a
second compare-and-set against the originally inspected row, clears the expired
lease, and leaves the job `PAUSED`. Explicit user cancellation is terminal and is
never converted into resumable work. Retry of `FAILED` or `BLOCKED_EXTERNAL`
returns the job to `QUEUED`; the new attempt is allocated only on acquisition.

## Progress and observations

The store exposes bounded `Flow` observations for the active queue, one job and
its event history. Progress units are intentionally coarse; there is no pixel
unit. Updates are coalesced unless stage/unit/total changes, completion is
reported, or both the minimum interval and minimum fractional delta are met.
The durable event history is trimmed transactionally to the configured bound.

## Database integration boundary

`ReconstructionJobEntity`, `ReconstructionJobEventEntity` and
`ReconstructionJobDao` are production contracts. `IsolatedJobStoreDatabase`
exists only to execute this assignment against a real Room database before Agent
005 registers those contracts in `ScanDatabase`. Application startup must not
open a second production database. Agent 005 owns the additive schema version,
exported schema and migration. Once integrated, construct `RoomJobStore` with the
application `ScanDatabase` and its `jobDao()`.

Project deletion must coordinate with Agents 005/006: either delete job/event
rows in the same durable deletion protocol or add an agreed foreign-key policy.
No job row authorizes deletion of originals or accepted artifacts by itself.

## Time and failure contract

Callers provide non-negative epoch milliseconds from one clock source. Lease
expiry is bounded to 24 hours and checked with overflow protection. Unknown
schema versions, enum values, malformed identifiers, invalid hashes and
inconsistent partial rows are rejected instead of interpreted as empty or
successful work.
