# Agent 094: canonical source provenance v1

Stage only your owned semantic changes, tests and receipt, then run from the checkout:

```bash
git diff --check
python3 tools/source_manifest.py generate --source index
git add SOURCE_MANIFEST.sha256
python3 tools/source_manifest.py verify --source index
git diff --check --cached
git diff --exit-code
```

Generation reads staged Git blobs, including staged additions/deletions/renames;
unstaged content never enters the generated manifest. `verify --source worktree`
(default) checks actual checkout bytes against the index's exact tracked file set.
`verify --source HEAD` or an immutable commit verifies Git blobs without trusting
worktree bytes. An index verification reads the staged manifest, so stage it first.
All failures return nonzero. The only hash exclusion is SOURCE_MANIFEST.sha256
itself; no file-count heuristic substitutes for equality of the exact tracked set.

Only UTF-8 canonical POSIX regular-file paths are supported. Symlinks, gitlinks,
control characters, backslashes, absolute/dot/parent components, duplicate rows,
noncanonical row ordering/line endings, unresolved conflicts and malformed hashes
fail closed. Executable files are supported. Resolve all semantic merge conflicts,
stage the resolved tree and temporarily stage the conflicted manifest, then generate
the entire manifest and stage it again. Never choose a side's manifest as final.

## Exact commit snapshots

```bash
python3 tools/ci/source_snapshot/archive.py create --revision HEAD \
  --output /tmp/source.tar.gz --record /tmp/source.json
python3 tools/ci/source_snapshot/archive.py verify --revision HEAD \
  --archive /tmp/source.tar.gz --record /tmp/source.json
```

The revision must resolve to a commit whose own complete manifest verifies.
The archive contains every regular tracked file in that commit, including its
manifest; tracked reports/docs remain source. No workspace walk is performed:
.git, ignored caches/build outputs, untracked credentials and dirty working files
cannot enter. There are no additional exclusions, including no silent secret-file
filter: do not commit secrets. Metadata is sorted paths, PAX tar with only file
entries, uid/gid/mtime zero, empty owner names and canonical 0644/0755 modes.
Gzip has empty filename, zero timestamp and compression level 9. Byte identity is
required for the same commit and Python/zlib implementation (CI pins Python 3.12);
compression differences across zlib implementations are outside this v1 policy.

The JSON record includes schema_version=1, source_commit, source_tree,
manifest_sha256, archive_sha256, archive_size_bytes, tracked_file_count and policy.
Verification reconstructs the canonical archive from Git and compares the complete
record and compressed artifact hash/size. Merely editing the record to match a
malicious archive cannot pass. A record is provenance, not a cryptographic signature.
Consumers 093/095/099 must retain both archive and JSON and bind them to the named
candidate commit. No impossible self-referential source SHA is embedded in source.
