# C2 reconstruction orchestration contract

Owner: Agent 002
Schema: `PipelineStageIdentity.SCHEMA = 1`
Implementation package: `com.realityforge.scanner.engine.pipeline`

## Purpose

C2 is the typed boundary between durable job/lifecycle owners, reconstruction providers,
artifact persistence, and atomic publication. It prevents a sparse point cloud, dense point
cloud, observed mesh, or photographic mesh from being represented as another stage merely
because a fallback file exists.

The current `SparsePipeline` and `DensePreview` implementation remains the initial backend
adapter. It now emits C2 stage identities and terminal outcomes while provider owners replace
individual stages incrementally. The generic `PipelineGraph` is executable now and is the
single orchestration point for durable runners once Agent 009 supplies persistent checkpoints.

## Stage DAG and representation

| Stage | Parent | Successful representation |
|---|---|---|
| `FEATURES` | none | `FEATURE_SET` |
| `MATCHING` | `FEATURES` | `VERIFIED_MATCHES` |
| `SPARSE` | `MATCHING` | `SPARSE_POINTS` |
| `DENSE` | `SPARSE` | `DENSE_POINTS` |
| `SURFACE` | `DENSE` | `OBSERVED_MESH` |
| `TEXTURE` | `SURFACE` | `PHOTOGRAPHIC_MESH` |

A runner may return `Unavailable(PipelineFailure)` for its own stage. The graph terminates at
that boundary and retains only already completed lower-fidelity artifacts. In particular,
texture failure leaves a completed observed mesh, but cannot create a completed photographic
mesh outcome.

## Immutable input and identities

`PipelineInputSnapshot` binds:

- project ID and exact source revision;
- ordered immutable photo IDs, content SHA-256, dimensions, byte count, and focal metadata;
- canonical calibration identity;
- explicit engine version;
- versioned settings for each stage; and
- an export settings identity that is intentionally excluded from reconstruction identities.

Every `PipelineStageIdentity` contains the exact parent digest. The invalidation contract is:

| Change | First invalidated stage | Result |
|---|---|---|
| photo content/order/revision | `FEATURES` | every stage recomputes |
| calibration/focal geometry metadata | `MATCHING` | features may be reused; matching and descendants recompute |
| feature settings or engine version | `FEATURES` | every stage recomputes |
| matching settings | `MATCHING` | matching and descendants recompute |
| sparse settings | `SPARSE` | sparse and descendants recompute |
| dense settings/resource tier | `DENSE` | dense, surface, and texture recompute |
| surface settings | `SURFACE` | surface and texture recompute |
| photographic texture settings | `TEXTURE` | geometry is reused |
| export format/settings | none | reconstruction is reused |

Identities use length-prefixed SHA-256 fields rather than delimiter concatenation. A runner is
rejected if it returns an artifact with a different identity or representation.

## Checkpoint protocol

Agent 009 implements `PipelineCheckpointStore` durably:

```kotlin
suspend fun latest(projectId: String, stage: PipelineStage): PipelineCheckpoint?
suspend fun commit(checkpoint: PipelineCheckpoint)
```

The graph reuses a checkpoint only when all of these are true:

1. the checkpoint is committed;
2. its full stage identity equals the expected identity;
3. project ID and source revision match;
4. its artifact identity equals the checkpoint identity; and
5. its representation equals the stage's declared representation.

`commit` is called only after runner output passes those checks. An implementation must make
the checkpoint and referenced artifact visible atomically; an in-progress or truncated write
must never be returned from `latest`.

## Execution, progress, cancellation, and result

`PipelineGraph.run` executes in stage order to a requested terminal stage. It returns a
`PipelineResult` with:

- terminal state (`COMPLETED`, `PARTIAL`, `FAILED`, or `CANCELLED`);
- exact project/revision and requested stage;
- a typed artifact map;
- structured failures; and
- a trace identifying `REUSED`, `EXECUTED`, `RECOMPUTED`, `UNAVAILABLE`, or `CANCELLED` work.

`PipelineProgress` identifies the typed stage rather than relying on display text. Explicit
runner cancellation returns a cancelled result. Coroutine cancellation remains structured:
`PipelineCancelledException` extends `CancellationException` and carries the exact last-valid
partial result while still propagating cancellation to the caller.

No checkpoint is committed for a failed or cancelled stage.

## Capacity admission

`PipelineCapacityPolicy` is used by the actual `SparsePipeline.run` entry point before any
photo selection. `LEGACY_12` is admitted. Target profiles `TARGET_30`, `TARGET_100`, and
`TARGET_250` are represented explicitly but rejected until their combined camera, track,
memory, geometry, and physical-device qualification exists. The entry point no longer uses
`take(12)` and never silently discards photos.

## Current adapter output

`SparsePipeline` writes a `pipeline` object into the revision-bound result JSON containing:

- contract and schema;
- admitted profile and input count;
- engine version;
- all six stage identities and parent identities; and
- a terminal completed/unavailable outcome for every reached stage, including artifact
  location, representation, optional content hash, or structured failure.

`DensePreview.reconstructTyped` returns typed dense/surface/texture outcomes while preserving
the existing `reconstruct(...): JSONObject` compatibility adapter for current tests/callers.

## Owner handoffs

- Agent 001 / 008: invoke `PipelineGraph` from immutable operation/job context; consume
  `PipelineResult` and preserve structured cancellation.
- Agent 009: persist `PipelineCheckpoint` and serialize/validate `PipelineArtifactReference`
  without redefining C2 stage semantics.
- Agent 023: atomically publish the artifact set referenced by completed outcomes; publication
  must not convert unavailable optional stages into success.
- Stage algorithm owners: implement `PipelineStageRunner`; return only the representation
  assigned to the requested stage and retain the supplied identity unchanged.

Any incompatible change requires a new schema and an explicit adapter or rejection path.
