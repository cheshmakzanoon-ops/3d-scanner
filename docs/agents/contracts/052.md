# 052 experimental Vulkan cost-volume reduction

The production selection is `CpuDefault`. No shipping profile is qualified or
enabled. `ExperimentalValidation` performs actual packaged SPIR-V compute on a
capability/budget checked Vulkan device and compares every output with CPU
reduction; driver/allocation/unsupported/parity failures preserve CPU output and
report a typed fallback. It never labels a CPU fallback as Vulkan success.

The narrow kernel consumes pixel-major float `1-NCC` costs from046/048, explicit
validity masks (after reference patch variance/mask tests), and the same inverse
camera-z planes, endpoint exclusion, non-neighbor uniqueness and quadratic peak
interpolation as current CPU046. It does not replace reciprocal consistency049,
produce a mesh, or claim a photometric candidate is verified scene geometry.

Tiles are bounded to65536 pixels and4194304 costs; caller budgets cannot exceed
hard caps. Combined bytes count input+CPUreference+GPUcost/mask/output+CPUreadback
simultaneously, including Vulkan padded allocation requirements. Rejected input
includes nonfinite costs, masks outside0/1, subnormal/extreme/unrepresentable
inverse-depth endpoints and zero inverse step. Shader asset and checked-in SPIR-V
header are offline; NDK glslc and spirv-val reproduce/verify the module.

Host software llvmpipe dispatch is useful numerical execution evidence, never
Android GPU/thermal/performance evidence. Fence polling checks cancellation every
1ms while draining an already submitted tile; buffers are not freed in flight.
A hung driver can still block fence completion/device destruction. Hardware
cancellation/driver-loss/thermal/combined memory qualification is NOT_RUN and is
a required gate before enabling any shipping Vulkan profile. The CPU path remains
available and default; compilation or software-device execution is not speedup.
