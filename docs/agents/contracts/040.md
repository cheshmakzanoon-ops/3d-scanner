# Agent 040 — supported sparse geometry and window mappings

Existing normalized ViewPose/TrackObservation/C ABI layouts are preserved. Each native invocation remains capped at12 calibrated cameras,100000 observations and30000 tracks; larger source collections use explicit windows rather than lifting solver limits. `NativeWindowMapping` binds compact native camera/track indices to unique source identifiers. `reconstructMultiViewWindow` validates the complete mapping and returns immutable source identifiers with every supported point. Global identifiers never pass through lossy double or transient snapshot ordinals.

SparseTrackPoint adds actual retained supporting camera indices and angular conditioning `1/max(sin(observed pairwise ray angle))`. This is sensitivity evidence, not posterior covariance, meters, whole-object completeness or a quality percentage. JSON adds trackEvidence without changing legacy point rows or schema semantics. Invalid/unbounded poses are rejected. Per-track and point-refinement cancellation checkpoints preserve operation isolation. The complete exported C function catches allocation and error-serialization failures and returns null rather than escaping C++ exceptions.

New numerical, source-window mapping and allocation-failure regressions run via the owned `tests/test_agent_040_native.py`, which compiles the actual focused C++ test against this checkout's built shared library. Production JNI and real-phone qualification are distinct gates.
