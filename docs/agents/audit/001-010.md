## What the checkpoint evidence establishes

Production provenance is written after the relevant bytes are synced. The runner then
acknowledges the exact immutable input or manifest hash to Room under its current lease.
A killed writer cannot advance the cursor before its record exists. A late writer cannot
advance another attempt's cursor. A resource pause before acknowledgment leaves reusable
files without pretending they are a current completed project result.

The sparse checkpoint stores the actual registered cameras, accepted world points and
matched feature observations. Its validator recomputes the projection of each point into
each observing camera, checks positive camera-space depth, compares measured normalized
RMS with the recorded RMS, rejects a feature assigned to two landmarks, and requires the
camera graph to be supported by shared accepted tracks. A valid file checksum is only the
integrity prerequisite for those geometry checks.

The job's revision and attempt remain part of every serialized ownership record. Content
identities exclude the revision counter so a rename or explicit rebind does not force
feature extraction. Photo inclusion/order, exact original hash, canonical optical/still
metadata, calibration, coordinate convention, assumed focal length and actual consumed
algorithm settings remain in their relevant identities. The persisted resource selection
is immutable for the job; geometry and appearance consume separate sub-identities.

Failed optional stages receive explicit failed manifests and their measured reasons.
They never receive completed mesh/texture artifact declarations. The current completed
project pointer advances only through the verified result-set publication transaction;
the previous completed result remains available throughout processing, pause or failure.

## Runtime ownership and remaining qualification

The activity still forwards `onStop` to `onHostStopped`, but the ViewModel hook is
now a no-op for CPU work. Reconstruction is actually service-owned. Keeping the hook
does not preserve the old cancellation policy. The assignment explicitly requires
runner lifecycle evidence before treating this change as accepted; the new real
platform harness is supplied and its execution remains an open gate.

The original publication protocol is an explicit 006/023 adapter under C6. C7 remains
the execution-lifecycle contract; the generic immutable result-set gateway is not
misrepresented as the publisher of legacy original rows. Compatibility-only storage
adapters remain available for historical constructors/tests until replacement device
verification permits their retirement; production composition uses the durable providers.

The 2–12-photo compatibility path remains bounded. Requests for 30/100/250 photos are
explicitly rejected as unqualified rather than truncated. The later scalable camera,
track, geometry and physical qualification assignments are not claimed implemented
by this audit of agents 001–030.
