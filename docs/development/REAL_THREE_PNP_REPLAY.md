# Fixed licensed-three PnP replay diagnostic

This is test-only, inside the already-failed partial-result branch of the exact10/11/12 licensed HOST fixture. No production source, threshold, matching, detector, native solver or logging hook changes. The original strict-three assertion remains primary. The helper never publishes a model or changes accepted state.

After the actual worker stops, the fixture verifies original hashes/metadata, job input/settings hash, fixed estimated88mm fallback with no photo focal metadata or calibration, complete physical input mapping and the persisted failed attempt's photo/count/reason/registered basis. It opens a separately owned native cancellation token; a child watchdog starts UNDISPATCHED on Dispatchers.Default and cancels the token when the existing30second diagnostic timeout fires. Shutdown joins that watchdog before finishing the token. This does not extend the outer HOST budget or claim arbitrary synchronous I/O can be interrupted.

The helper uses no photo decoder, descriptor matcher, FeatureCache.load (which updates LRU mtime), checkpoint publisher or AdmittedRegistrationSession. It reads exactly6already-existing canonical nonsymlink files:3feature entries, match graph+checksum and frontier envelope. FeatureCacheFormat.decode is production code. Narrow test-only version-bound parsers decode match-v3 and frontier-v1 envelopes and reuse FeatureMatchRecord/RegistrationFrontier validation; no new production file API is added. Unexpected versions, missing files, malformed bounds, changed bytes/size/mtime/creation/file identity or replaced root identity refuse the diagnostic. Access time is not compared because an ordinary read may update it.

Feature inputs are conservatively limited to3500rows/1600edge, frontier envelope1MiB,3pair graph,2anchor cameras and16..128PnP rows. These are diagnostic refusals, not widened production admissions. Feature bytes use the existing12MiB codec limit and bounded reads; full descriptor data may exist transiently in decoded records but are never exported. Coordinates/colors preserve original cached row order. Cached rays are checked against the exact production estimated lens for their source keys. Saved camera poses must match the published partial preview. Exact source/settings/cache hashes, input identity and physical source mapping bind replay provenance.

Production IncrementalRegistration.grow runs directly against these cached keys with a no-op checkpoint and actual NativeFrontierGeometry callbacks. Source triangulation and pose-call inputs are hashed; the exact16..128×5XYZ+normalizedUV register buffer is copied before native invocation. A second use of production MultiViewTrackGraph reconstructs source membership from the same cached keys and must pack byte-identically to the actual triangulation callback input. The report includes the two anchor R/t transforms, all3estimated projection models, and only the contributing source camera/key/normalizedUV observations plus links into each candidate key. Geometry-equivalent origins are retained as a bounded list (at most8per row) and explicitly marked ambiguous rather than assigned invented unique provenance. A replay is labelled VERIFIED_REPLAY only if exactly one triangulation and one registration occur, the registered basis remains2, candidate photo matches, actual row count equals this run's persisted attempt count, and the bounded numeric native failure suffix agrees. Historical45is not hardcoded. All native gates remain active. There is no fallback extraction/rebuild, no accepted-pose mutation and no full-private-cache/database/original-image export.

`measurement/pnp-replay.json` has a closed schema,65,536byte cap, finite bounded numbers, binary-double row SHA256, fixed original hashes and hash-only cache/source-array provenance. The validator binds exported anchor poses to poseRowsSha256, candidate threshold to its projection focal, source labels to the two anchor poses, source links to candidate keys, and positive-depth source reprojection to the existing6/focal supported-landmark bound. Track IDs, candidate keys and source(camera,key) identities cannot be claimed by different output rows. Numeric signedzero is preserved by the Python verifier even when org.json spells -0.0 as -0. The Python verifier rejects unknown fields, duplicate JSON keys, giant/nonfinite numbers, foreign profiles, malformed hashes/counts/failure claims and duplicate geometric rows. Packaging requires failed overall receipt and no complete-result marker; this artifact is never part of required successful result documents. Existing immutable CC BY attribution and real-input privacy checks remain mandatory.

Classification is `READ_ONLY_REPLAY_NOT_ORIGINAL_CALL_NOT_QUALITY`: these are replay-generated numeric inputs, NOT instrumentation of the original native call. Agreement of source hashes/count/failure is diagnostic reproducibility evidence, not previously unavailable bytewise proof of the original45rows. Hashes of the complete source observation buffer and returned triangulated point buffer bind intermediate provenance; only contributing observations are exported, never the full source graph or descriptors. Missing/mismatched cache or callback evidence yields only DIAGNOSTIC_FAILURE/READ_ONLY_REPLAY_UNAVAILABLE, never a model or PASS.

Local executable controls use actual Kotlin growth/cache/frontier code with analytic callbacks, not JNI or photographic qualification. The isolated portable compilation uses the exact standalone FeatureMatchRecord class text from its production file to avoid importing unrelated Android-adjacent artifact-session dependencies; the actual HOST compiles the full production classes. Full real-source-bound HOST replay remains NOT_RUN until executed. Required tests cover malformed envelopes, unknown identities, tampering even after checksum update, candidate/pose/count/reason mismatch, cancellation, replacement/symlink/mtime identity, unchanged files, strict-failure preservation, row-schema privacy, and accepted-state immutability.
