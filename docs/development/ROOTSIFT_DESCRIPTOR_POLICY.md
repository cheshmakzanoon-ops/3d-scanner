# RootSIFT descriptor policy

Extraction now converts each retained SIFT histogram once to `sqrt(d / L1(d))`, before FeatureFrame publication and persistence. Keypoint coordinates, row ordering/count, colors, decoding, resizing, detector settings, 3500 cap and reciprocal L2 ratio0.67 are unchanged. Matching and every geometric gate remain unchanged. The feature stage is chosen rather than repeated matcher conversion to amortize normalization per photograph and leave the generic matcher/oracle unchanged.

`RootSift.normalizeRow` is pure Kotlin, requires separate input/output arrays of exactly128 floats, validates all finite nonnegative values before writing, accumulates in Double, and rejects zero-sum histograms. Zero histograms are not replaced, dropped or assigned invented matches. Negative/NaN/infinite rows fail closed. The production adapter normalizes its owned descriptor clone, not borrowed pixels or raw keypoint data, using two reusable128-float buffers (1KiB scratch), checks cancellation before each row, and releases the owned Mat on failure before publishing any frame. No descriptor-matrix-sized JVM scratch or per-row arrays are allocated by production normalization. The1KiB is incremental JVM row scratch, NOT total extraction peak: the raw SIFT Mat, retained clone (512bytes per retained row), and SIFT native workspace remain live during this work.

The float[] OpenCV4.12 get/put return values are **bytes**, not elements: official `modules/java/generator/src/cpp/Mat.cpp`, `mat_copy_data<T>` returns `count * sizeof(T)` bounded by remaining bytes, and both `nGetF` and `nPutF` delegate to this implementation. Each128-float transfer requires512 bytes. The host test independently checks this contract and row isolation. Source: https://github.com/opencv/opencv/blob/4.12.0/modules/java/generator/src/cpp/Mat.cpp

Extractor identity changes from rf-sift-v2 to `rf-sift-v3|rf-rootsift-l1-sqrt-v1`. SparseFeatureCache already binds its key and encoded identity to ExtractorSettings.identity, and FEATURES stage settings use that same identity. Thus old raw-SIFT feature entries cannot be loaded as RootSIFT; unchanged binary cache encoding can safely retain both semantic identities. All dependent MATCHING/SPARSE/DENSE/SURFACE/TEXTURE/EXPORT stage identities change. SparsePipeline's durable frontier fingerprint is the SPARSE stage digest, so old frontier checkpoints are not reusable. Original photo bytes and hashes do not change. Tests exercise old-cache refusal, RootSIFT round-trip ownership and all-stage identity propagation. Three explicit host compiler inventories also bind the new helper source.

## Evidence boundary
The motivating private paired desktop experiment on licensed skull10/11/12 kept identical decoded gray/keypoints/raw descriptors and ratio0.67. RootSIFT increased distinct final-reference-E-supported matches232→258,68→82,22→24, while adding2 and1 inconsistent distinct matches on weaker pairs and slightly increasing residual medians. That comparison is not Android-pixel equivalent, pose ground truth, a third-camera registration pass or a finished scan. Native geometric admission remains mandatory.

Pure Kotlin numeric/cache/stage tests execute locally. The actual OpenCV extraction host oracle now independently computes expected sqrt(L1) descriptors from raw SIFT, retaining exact keypoint/color/order assertions and adding transfer/cancellation checks. If a verified Java OpenCV runtime is unavailable, that host test is NOT_RUN, not synthetic qualification. A fresh source-bound actual HOST run and unchanged JNI pose gates are required before any quality claim.
