# Projective-band allocation enclosure — source-review argument, not a test result

Applies to exact v2 `bandBounds`, `lookup`, `integrate`, `boundGrid` operation order. Assumptions enforced in code/config: IEEE binary64, nearest rounding, positive finite intrinsics/maps, validated image widths/heights<=640 and stride2..8, original finite pose validation, prototype no fast-math/contraction, finite interval arithmetic, and checked lattice indices strictly bounded by1e9 before the one-index enumeration halo. A nonfinite enclosure or determinant interval containing zero fails the candidate. No claim that an unreviewed alternative operation order has this bound.

Let u=2^-53 and gamma_k=k*u/(1-k*u). Code's gamma64 is rounded upward. Elementary interval add/subtract/multiply/divide endpoints are expanded with nextafter to contain exact elementary real results. This also encloses subnormal arithmetic; nonfinite results fail. Source lower/upper extrema are represented finite map floats and pixel integers.

1. **Accepted canonical image coordinate is in an expanded source cell rectangle.** `lookup` first requires projected U in[3,width-3), then computes g=fl(fl(U-3)/stride). A selected cell's integer index k either equals floor(g), or is its immediate predecessor ONLY when g is exactly integral. Hence g in[k,k+1] for either selected cell. The error in recovering real U from3+stride*g is bounded by gamma2*(width+3), plus negligible subnormal absolute terms; the code uses the strictly larger outward gamma64*(width+stride+3). Width is validated<=640. The same argument holds for V and height. Every admitted triangle's x/y extrema are exactly those of its original square cell, so the entire expanded rectangle encloses all such accepted points regardless of barycentric classification rounding. No claim that the triangle itself expands. This is the explicit v2 correction missing from unexecuted v1.

2. **Computed harmonic depth is enclosed.** Accepted computed lambdas lie in[0,1], with l2=fl(fl(1-l0)-l1). Their exact represented-value sum differs from1 by at most2u (both subtraction absolute errors are bounded by u at these magnitudes, plus subnormal rounding). Thus the exact positive weighted reciprocal sum lies between(1-2u)/zmax and(1+2u)/zmin. Three divisions/products, two positive additions and final reciprocal introduce fewer than16 sequential relative-rounding factors; no denominator cancellation. The existing sample/map bounds keep the denominator away from underflow. Gamma64 conservatively dominates these factors and the lambda-sum error. Code encloses D in[zmin/(1+gamma64),zmax/(1-gamma64)] using interval division, not ordinary rounded scalar division.

3. **Near-band camera-z enclosure.** If computed r=fl(D-qz) satisfies -mu<r<=mu, the exact subtraction D-qz lies between the adjacent floating neighbors of[-mu,mu]. Inverting this subtraction gives the interval `z=depth-expand([-mu,mu])`. Finite qz<=.01 is excluded before projection, so intersecting the lower bound with.01 cannot omit an admitted point. The inclusive lower allocation bound is deliberately looser than the strict contribution branch at-mu.

4. **Inverse floating projection.** Integration computes U=fl(fl(fx*fl(qx/qz))+cx), not an unspecified equivalent algebraic ordering. Starting with the expanded rectangle U interval: expand it to enclose the preimage of the final addition; subtract cx outward to bound the stored product; expand again to enclose the product's rounding preimage; divide by positive fx outward to bound the stored quotient; expand again for division's rounding preimage; multiply by the camera-z interval. This is exactly `ray()` followed by `times(ray,z)`. It bounds the represented qx used by integration. Likewise qy. The third q component is the bounded qz, not zero or an omitted initializer.

5. **Grid multiplication plus floating camera transform error.** Let Y_k=index*pitch in exact real arithmetic and X_k=fl(Y_k) be the stored lattice component. Both |Y_k| and |X_k|<=(1e9+2)*pitch outward, from accepted grid bounds and the one-index halo. The first multiplication rounding X_k-Y_k is included in the gamma64 envelope, not treated as exact. The pinned native `multiply(Mat3,Vec3)` computes three products and two additions per row; `cam` adds translation. Gamma64*(sum_j|R_ij|*max|X|+|t_i|)+64*denorm_min encloses the error between represented q_i and BOTH exact R_i Y+t_i and exact R_i X+t_i: grid multiplication plus three row products/two additions/translation needs fewer than8rounding factors, well below64. Code computes this error bound outward, expands q_i symmetrically by its high endpoint, then subtracts t_i outward. Fused arithmetic, if present inside the pinned engine, does not enlarge this conservative unfused-rounding envelope.

6. **Actual inverse, not transpose.** Interval cofactors/determinant/adjugate division enclose the inverse of the represented stored matrix R. The determinant interval must be strictly positive. Multiplying the bounded exact R Y and R X by this inverse interval encloses both exact mathematical grid Y and stored rounded X. Tolerated nonorthonormal rotations are covered; no orthonormal-exactness assumption is used for allocation. This does not change the original pose, source XYZ or final witness.

7. **Enumeration.** `boundGrid` outward-divides the world intervals by positive pitch before floor; enumeration extends through upper floor+1. Because the preceding envelope includes the exact mathematical grid point Y=index*pitch (not only X=fl(Y)), outward interval division by pitch contains the exact integer index. The lower floor and upper+1 therefore include each admitted lattice index without treating stored multiplication as exact. Product/count/grid checks precede loops. Any overly conservative extent can exceed the unchanged budgets and fail; it is never silently truncated or coarsened.

This proof is allocation-only. It does not make a triangle normal into a field gate, enlarge the canonical observed domain, change the near-band policy, relax the source depth-jump/edge/area gates, or enlarge the whole-face witness slab. The rectangle-frustum overbound is deliberately looser than the exact harmonic triangle band. All accepted nodes still require an actual canonical near-band observation; front-only/unknown cells remain absent.
