# Frozen evaluation-only depth-stage census

This evaluator consumes immutable outputs of the already sealed oracle-camera component. It never calls reconstruction, changes source plans, estimates poses, or supplies truth to a solver. Geometry/masks are read exclusively for evaluation. Keep all 6,000 reference samples and the identical 3,734 observable subset (seed 78425, same convex visibility/6 pixel margin); retain every visible sample/view row, including grid-ray face transitions and background. All eight cameras remain present.

The pinned native source uses patchRadius 2, origin r+1=3, stride 2, and loops x<width-r-2 / y<height-r-2: x 3..155 and y 3..115, 35,112 sites total. Native nearest sampled neighbor uses std::round ties away from zero. Evaluator selection reproduces that arithmetic but is NOT a new native consistency query. Record exact sample projection and grid offset. Every positive retained map entry must lie on the declared grid, and all actual native attempts/generated IDs are re-audited by the unchanged complete witness auditor. Native photometric values, zero maps and verified membership remain distinct.

Truth depth comes from the same pinned perspective-correct raster evaluator at the selected grid pixel, never the original sample depth at a different ray. Same physical face, other face and background are explicit. Face identity means identical outward normal on this fixed convex cuboid, not a general nonconvex rule. Each visible sample/view gets a mutually exclusive pipeline stage plus independent error and face labels. Highest retained stage across views is an accounting aggregate, not accurate coverage. Error fractions 0.5/1/2/5 percent of reference diagonal are existing descriptive evaluator thresholds, not optimizer settings.

All-point necessary reachability at 1 percent reuses the frozen rho 0.04965026414510365 solely to stratify the complete evaluation; no sample is dropped or acceptance tuned. Raw NCC rejected-winner/alternative reasons are UNAVAILABLE. Zero depth does not prove texture failure. Actual directed confirmation categories are not relabeled exact mutual identities.

Limits frozen before measurement: 1 GiB process address space, 120 seconds CPU/wall, at most 29,872 visible sample/view rows, 12 MiB data +1 MiB combined log allowances +1 MiB helper binary +1 MiB receipt/refusal within 16 MiB total. Abort rather than truncate. Inputs and package hashes must remain unchanged. No binaries or large generated data belong in the compact publication.

Before census execution, compile a small original std::round control with the available /usr/bin/c++ and compare 2,406 exact ties/adjacent nextafter cases against the evaluation helper (including the complete native origin/stride expression). No production source is changed. Each helper is bounded; compact compiler/source identities are recorded.

Projection precision: reference samples and oracle camera arrays are evaluator binary 64 values; projection uses the unchanged NumPy evaluator path, not the native C++ multiply operation order. Stored camera arrays are checked exactly against native inputs.bits, but reference projections are evaluation queries, NOT bit-identical executed native observations. The round helper matches std::round on its computed double operand. Float 32 native depths/confidence remain read from original bits; the unchanged native witness auditor separately checks actual executed projection/reprojection evidence. No native projection-bit-parity claim is made for truth reference samples.

The modf helper is generic-domain hardening, not a demonstrated fixed-fixture defect. Independent actual-v tests of the original helper passed. No previous whole census exists to invalidate.

Log allowances are 192 KiB native-rounding log, 32 KiB compile log, 32 KiB check log and 768 KiB execution log (sum 1 MiB). The compiled helper is checked≤1 MiB before any census data writes, and the compiler itself has 1 MiB file-size limit. These are separate suballocations, not an increased total budget.
