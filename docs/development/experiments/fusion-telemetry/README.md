# Original-fuser telemetry: exact-input host diagnostic

**Result: measurement, not an algorithm change or quality improvement.** A fresh COMPACT capture was replayed with the immutable original engine and a separate test-instrumented engine. Live capture, original replay and traced replay matched exactly on logical raw mesh bits, native PLY and complete mesh JSON before any counters were admitted. Source/tool/input hashes remained unchanged. This fresh run has **6,190 intersections and 6,741 faces**; it is not the earlier 6,137-pair provenance run.

## What was measured

Of 6,867 input samples, only **1,014 (14.77%)** had a supported recomputed depth-neighborhood normal. The unchanged normal routine returned early at a nonpositive neighbor depth for **5,306**, and at a depth jump for **43**; **504** fitted neighborhoods were ill-conditioned. No boundary, center-unavailable, nonfinite-neighbor, confidence-unavailable, unit-normal or plane-bound rejection was recorded. The original enum calls missing-depth and depth-jump exits `Discontinuity`; do not relabel these as `Sparse` or interpret the label as proof of a real physical edge.

Of 6,865 accepted samples, 271 fused and 6,594 started a new accumulator. There were 69,094 candidate visits: 26,673 first rejected as same-camera, 34,991 at incoming-normal support, and 2,408 at accumulator-normal support. All fifteen first-rejection categories are retained in the summary. **276 candidates passed all gates, but only 271 samples ultimately fused**; visits/passes are not sample outcomes. All 271 fused samples had supported recomputed normals. These are original recomputed neighborhood observations, not stored checkpoint normal flags.

The normal-support checks are active constraints in this fixture. This does **not** establish that any guard is wrong, that missing evidence is safe to interpolate, that relaxing it improves quality, or that all crossings share that cause. First-rejection counts depend on unchanged branch order. The nine-neighbor support, depth jump, confidence, conditioning, radius, visibility and pair/anchor guards were preserved.

## Reproduction and evidence

`diagnostic/telemetry.patch` applies only to a private copy of baseline native sources; base/patched hashes are in `source-pins.json`. Add `snapshot.hpp` and `telemetry.hpp` to that private include directory. No files are installed into production. The patch preserves numeric expressions and short circuit order, collecting actual normal validity/early returns and candidate first-rejection counts.

1. `run_stagea.py` builds the private copy with GCC14/C++20/Release/Werror, maximum2jobs and2GiB per process; runs3 existing native tests,37 snapshot guards and10 comparison cases. Config must pin actual canonical source/tool/header paths and expected hashes. It imports the sibling `compare.py` helpers. StageA v1 failed on two formatting warnings; V2 changed braces/newlines only, without suppressing warnings.
2. `shim/build_shim.py` builds original JNI source into a new shim with fixed private-engine RUNPATH, checks exact engine resolution and28 original JNI exports. Original engine/shim remain immutable. No LD_LIBRARY_PATH redirection. Named tool/source/header pins do not claim complete operating-system/linker closure.
3. `capture/` reconstructs the host capture delta against the committed validation harness; includes the preserved compile-only failure and minimal actual-proc PID fix. Successful capture binds exact snapshot/raw mesh and before/after actual JVM mapped engine/shim path/device/inode/hash. It preserves all original fixture assertions and restores normal compiled classes. Raw images, snapshots, binaries and full captures are not duplicated here.
4. `diagnostic/compare.py` compiles two small replay executables against original/traced engines, then replays the exact same frozen snapshot in separate processes. It validates the completed restored-PASS capture, manifest/raw artifacts and actual JVM maps before replay. Three-way raw mesh/native PLY/full JSON equality gates all telemetry interpretation. The successful run used550 pinned inputs,2GiB per process,60s compile/replay limits and300s aggregate process-group supervision; native engines were not rebuilt.

Machine-local configs are intentionally omitted: derive canonical paths and hashes from a new reviewed environment and actual capture. Never substitute guessed camera IDs, regenerated images, rounded geometry or a different run's checkpoint. `evidence-summary.json` retains compact aggregates and original receipts/raw-count SHA256 references; large per-sample rows stay external. Original engine SHA4384f676ab950a3e615d286be8d8e9e4f16e28e22fa5fda4177b39445f6c786b and original JNI SHA427f2c8c0e21a5647064edcdbe9307265fe493c256c211e4266f979f9931fcce were unchanged.

## Next evidence step — not implemented or run

Before designing any alternate normal-support rule, read this same frozen snapshot to measure the nine-position depth/confidence availability mask for each verified sample; distinguish missing cardinal versus diagonal neighbors, complete windows, depth-jump failures, and overlap with the original normal-validity/sample-outcome rows. Report center-relative depth-jump distributions only for valid observed neighbors, not invented fills. Keep the original nine-neighbor guard unchanged. A bounded reviewed diagnostic reader must bind snapshot identity/trailer/raw hashes and reproduce original input normal/outcome counts before interpretation.

Only then decide whether a conservative controlled alternative has enough supported observations to merit an experiment. Any candidate would require discontinuity, occlusion, thin-opposing-sheet and sparse-invalid negative cases, plus same-input surface coverage/residual/intersection comparisons—not merely higher fusion counts. No candidate policy, threshold change, production patch, or follow-on execution is approved by this archive.
