# Physical resource protocol v1

Use actual ARM64 phone/candidate/input/settings identities; emulator and synthetic sampler tests cannot qualify physical budgets. All collection remains local. Use only authorized disposable test projects; native kernels/export paths execute for real.

Record conditions JSON before the run: ambient temperature, make/model, OS/build, screen brightness/refresh, battery start level/health, charging/cable status, cooling, selected profile, background applications and object/input manifest. Preserve raw traces outside Git.

Build debug APK and test APK. Start the bounded actual workload with `adb -s SERIAL shell am instrument -w -r -e class com.realityforge.scanner.agents.a087.ResourceProbeContractTest#profileOperatorSelectedDisposableProject -e resourceProjectId UUID -e resourceRuns 3 com.realityforge.scanner.test/androidx.test.runner.AndroidJUnitRunner`. This resets bounded debug events, records real pipeline boundaries/Java/native allocations/PSS/thermal status and runs the existing production SparsePipeline. Use a disposable imported project. Baseline processes at most12 sparse/eight depth views; 30/100/250 profiles stay disabled until their owners implement and qualify them. The instrumentation uses32.88mm assumed focal unless a project calibration exists; record that setting, do not claim a calibrated physical geometry measurement from an assumption.

Concurrently run `python tools/device/resource_profiling/profile.py collect --serial SERIAL --app-apk APP.apk --input-manifest INPUT.json --settings SETTINGS.json --conditions CONDITIONS.json --samples 120 --interval 1 --output PRIVATE/trace.json`. Installed base APK hash must match the supplied APK. Capture long enough for reconstruction/viewer phases, with2–3600 samples and0.5–10s spacing. Trace contains host monotonic samples, actual selected PID/start ticks where permitted, meminfo RSS/PSS and native/Java heap PSS, df free storage, debug run-as package disk size, thermal service status, and battery indicators. Debug events contain elapsedRealtimeNanos for stage correlation. Missing counters remain null; stale PIDs/events, sampling gaps or impossible counters fail analysis. Run `python tools/device/resource_profiling/profile.py analyze PRIVATE/trace.json --output PRIVATE/summary.json` to revalidate independently.

Perform cold launch (clean disposable install/caches only), warm repeat, at least three sustained reconstruction repetitions and a10-minute photographic viewer interaction trace. Use actual12-photo/eight-depth workloads first. Record observed duration, thermal transitions, pause latency using event timestamps, and sampled peak memory/package disk with sampling limitations. Stop through normal app controls if the handset issues thermal warnings. Never fill storage to induce pressure. Do not change CPU/GPU/thermal policy for a favorable result.

Battery level and charge-counter changes depend on gauge resolution/background load/charging; **energyJoules stays null**. Precise energy requires calibrated external power hardware or documented supported device counters. GPU allocation/counters require supported vendor/system tracing and separate provenance; CPU heap values cannot stand in for them. Missing `/proc/PID/stat` disables robust PID-reuse detection and is explicitly listed. For budget acceptance, require that counter or a reviewed alternate process-start identity. Sampling peaks miss transients; unsupported RSS/GPU/power counters require reviewed alternatives, never invented zeroes.

Budget recommendations to030/069/099 require exact physical candidate/settings/input receipt, trace integrity PASS, a reviewed supported-hardware/profile threshold contract, and all mandatory counters or approved alternatives. The analyzer's PASS means trace integrity only. No numeric profile budget is waived or inferred by this implementation. No actual phone run is available in this cloud environment; all physical resource/thermal/power gates remain BLOCKED_EXTERNAL/NOT_RUN.
